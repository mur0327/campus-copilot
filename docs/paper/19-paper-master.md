# 논문 집필 정본

작성일: 2026-07-15

최종 갱신일: 2026-07-17

**상태: 원고 집필 가능.**

이 문서는 논문의 목적, 연구 설계, 결과, 해석, 한계와 남은 작업을 한곳에서 관리하는 유일한 현행 집필 정본이다. 논문을 이해하거나 집필할 때는 이 문서부터 읽고, 과거 작업 문서와 원시 산출물은 맨 마지막의 근거 목록에서만 확인한다. 리뷰로 결정이 바뀌면 과거 문구를 누적하지 않고 이 문서의 현재 내용을 직접 고친다. 변경 이력은 Git과 별도의 외부 리뷰 기록에 남긴다.

## 1. 10분 요약

### 1.1 이 논문은 무엇을 하는가

이 논문은 대학 공식 웹 문서를 근거로 학사 안내 답변을 생성하는 RAG 시스템을 구축하고, 고정된 50개 질문에서 검색 회수, 내용 정확성, 근거 축, 배포 적합성과 최종 응답 행동을 분리해 관찰한 오프라인 사례 연구다. 기존 검색·생성 기법을 실제 공식 문서 도메인에 적용하고, 검색 성공만으로는 드러나지 않는 최종 응답의 실패 지점을 계보가 고정된 평가 절차로 나누어 확인한다.

### 1.2 왜 이 연구가 필요한가

공식 문서 RAG는 관련 페이지를 찾더라도 질문의 핵심을 담은 청크를 확보하지 못할 수 있다. 검색된 내용이 사실을 지지하더라도 지난 회차의 공지이거나 다른 사용자 집단을 위한 문서라면 현재 답변에 사용할 수 없다. 충분하고 적합한 근거가 있거나 부족하다는 사실이 확인돼도 생성기가 완전 답변, 제한 답변과 거절 중 적절한 행동을 선택한다는 보장은 없다. 따라서 페이지 검색 성공, 근거 충분성, 현재 배포 가능성, 최종 응답 행동을 한 점수로 합치지 않고 별도로 관찰할 필요가 있다.

### 1.3 연구 흐름

초기 평가는 질문별 정답 URL을 중심으로 검색 성공을 측정했다. 사례 검토에서 같은 페이지의 비지지 청크도 정답으로 계산되고, 관련 내용이 있어도 시점이나 대상자가 맞지 않는 문서가 답변 가능 근거로 섞이는 문제가 발견됐다. 이를 해결하기 위해 페이지 지지, 청크 근거, 시간 유효성, 대상자 적합성과 기대 응답 행동을 분리한 최종 평가 정답표를 구축했다. 세 검색 구성의 top-5 합집합과 기존 양성 근거를 판정 후보로 삼고, LLM 전량 초벌, 위험 기반 사람 감사, 질문 50개 전량 검토와 불일치 조정을 거쳐 정답표를 확정했다. 같은 정답표로 세 검색 구성을 오프라인 재채점하고, 현재 운영 Hybrid 구성으로 50문항을 세 번 실행해 첫 응답의 최종 품질과 세 응답의 구조화 행동 반복성을 평가했다.

### 1.4 작업 제목

**작업 제목:** 대학 공식 문서 RAG의 검색·근거·배포 적합성과 응답 정책 감사: 단일 기관 50문항 사례

최종 제목은 지도교수 검토에서 확정하고, 영문 제목은 국문 제목 확정 뒤에 작성한다.

### 1.6 핵심 결과

- 어느 한 검색 구성도 모든 검색 지표에서 우세하지 않았다.
- Hybrid는 완전한 페이지와 근거를 하나라도 회수한 비율이 가장 높았고, Semantic은 부분 근거를 포함한 회수와 두 nDCG에서 가장 높았다.
- 최종 응답의 엄격한 종합 성공은 31/50(62.0%)이었다.
- 완전 답변 기대 문항은 22/28(78.6%), 제한 답변 기대 문항은 1/3(33.3%), 거절 기대 문항은 8/19(42.1%)가 엄격한 종합 성공 조건을 충족했다.
- 과잉답변(사전 정의한 보수적 응답 정책과의 불일치)은 제한 답변 또는 거절이 필요한 22문항 중 13문항(59.1%)에서 관찰됐고, 이 중 3문항은 내용·근거·배포 축을 모두 통과한 정책 전용 불일치였다. 과잉거절은 완전 답변 또는 제한 답변이 필요한 31문항 중 0문항이었다.
- 엄격한 내용 정확성 실패는 12문항, 내용 지지와 표시 출처를 결합한 근거 축 실패와 배포 적합성 실패는 각각 6문항이었고, 세 축을 모두 실패한 것은 Q016과 Q031 두 문항이었다.
- 구조화된 응답 행동은 세 번의 실행에서 46/50(92.0%)가 모두 같았다.
- Q035를 제외한 49문항 민감도와 사람 감사 전후 검색 지표에서 핵심 해석과 검색 구성 순위가 유지됐다.

### 1.7 핵심 주장

> 본 대학 학사 안내 RAG 사례에서 최종 응답의 내용 정확성, 근거 축, 배포 적합성과 응답 행동은 동일한 성공·실패 집합으로 수렴하지 않았다. 별도의 검색 비교에서도 완전 근거 회수와 순위 품질 사이 trade-off가 관찰돼, 검색 결과와 최종 응답의 여러 품질 축을 한 점수로 합치지 않고 각각 평가하였다.

수치와 실패 빈도는 단일 대학, 고정 코퍼스, 목적 표집 50문항, 고정된 모델·프롬프트·평가 시점에 귀속한다. 본 연구의 함의는 산출물 계보를 추적할 수 있는 한 사례에서 검색 지표만으로 설명되지 않는 중간 실패 축을 함께 관찰했다는 데 있다. 다른 기관과 RAG 구성에서도 같은 분리가 나타나는지는 추가 검증이 필요하다.

### 1.8 기여

1. 고정된 단일 대학 공식 문서 코퍼스와 운영 RAG 경로를 목적표집 50문항 감사 문항셋에서 평가한 사례를 제시한다.
2. 기존 RAG 평가 개념을 페이지·청크 계보, 실제 주입 근거와 표시 출처, 시간·대상자 배포 적합성, 사전 정의된 보수적 응답 정책 준수로 연결해 적용한다.
3. 이 동결 실행에서 검색 지표별 최고 구성이 달랐고, 내용·근거·배포·정책 불일치가 서로 다른 문항 집합으로 나타났음을 기술한다.
4. qrel, 마스킹 응답, 판정·집계 산출물과 해시 계보를 제공해 산출물 수준의 감사를 지원한다.

### 1.9 주장하지 않는 것

- 새로운 검색 알고리즘이나 범용 RAG 평가 프레임워크를 제안했다고 주장하지 않는다.
- Hybrid 또는 Semantic이 일반적으로 더 우수하다고 주장하지 않는다.
- 엄격한 종합 성공 60.0%를 일반 정확도, 배포 합격률이나 실제 사용자 만족도로 부르지 않는다.
- 목적 표집한 50문항이 전체 학생 질문을 대표한다고 주장하지 않는다.
- 사람 감사가 후보 전량의 독립 이중판정이거나 평가자 간 신뢰도를 보장한다고 주장하지 않는다.
- 구조화 행동의 3회 일치를 답변 내용 전체의 안정성으로 일반화하지 않는다.
- 사람 감사 뒤 달라진 검색 지표를 시스템 성능의 향상이나 저하로 해석하지 않는다.

### 1.10 현재 단계

최종 평가 정답표 구축·감사·발행, 세 검색 구성 재채점, 최종 응답 실행·판정·발행, 마스터 통합, 관련 연구 재조사(§13), 외부 게이트 리뷰와 제목·기여 확정은 완료됐다. 다음 단계는 실제 원고 집필이며, 서술 규칙은 §15와 각 절의 집필 통제를 따른다.

## 2. 연구 서사

### 2.1 출발점

대학 학사 정보는 학사 안내, 공지, 학과와 별도 기관 사이트에 흩어져 있고, 같은 주제의 문서라도 적용 시점과 대상자가 다르다. 본 시스템은 공식 문서를 수집·색인하고 질문과 관련된 청크를 검색해 구조화된 답변과 출처를 생성한다. 초기 연구 질문은 관련 정답 문서를 top-k 안에 회수할 수 있는지에 집중했다.

### 2.2 측정 문제의 발견

URL 중심 검색 평가는 페이지가 한 번 등장하면 실제로 검색된 청크가 질문을 지지하지 않아도 성공으로 계산할 수 있었다. 기존의 답변 가능·불가능 구분은 코퍼스에 답이 없는 경우, 필요한 청크가 수집되지 않은 경우, 답은 있지만 지난 회차인 경우, 문서 대상자가 질문자와 다른 경우를 한 범주에 섞었다. 이 문제는 검색 실패와 배포 부적합, 근거 부족과 거절 필요성을 구분하지 못하게 했다.

### 2.3 평가 재설계

최종 평가는 질문, 페이지와 청크를 서로 다른 단위로 판정한다. 페이지는 질문 지지 정도, 시간 유효성, 대상자 적합성을 각각 기록한다. 청크는 실제 텍스트가 질문을 완전 또는 부분 지지하는지와 페이지 도달 자체가 근거인지를 기록한다. 질문은 최종적으로 완전 답변, 제한 답변과 거절 중 기대 행동을 기록하고 그 이유를 필수 주장 부족, 수집 실패, 시점 만료, 판정 pool 내 근거 부재와 대상자 불일치로 분리한다.

### 2.4 최종 관찰

분해된 정답표에서 Hybrid와 Semantic은 서로 다른 검색 지표에서 앞섰다. 최종 응답에서는 사실과 근거가 맞아도 시점이나 대상자가 맞지 않는 사례, 내용은 배포 가능하지만 표시 출처가 부정확한 사례, 내용·근거·배포 축을 통과해도 기대한 제한 또는 거절 행동과 다른 사례가 각각 관찰됐다. 본 논문은 검색 비교의 trade-off와 최종 응답 안에서 서로 다른 평가 축이 분리되는 지점을 각각 설명한다.

## 3. 연구 범위와 분석 단위

### 3.1 연구 성격

본 연구는 단일 대학의 공식 웹 문서 코퍼스와 한 운영 구성을 대상으로 한다. 분석 범위는 동결된 검색 결과와 구조화된 최종 응답을 이용한 오프라인 관찰 사례다.

### 3.2 질문 집합

평가 질문은 학사 행정 영역의 목적 표집 50문항이다. 초기 20문항을 50문항으로 확장했으며, Q021~Q026 여섯 문항은 2026년 7월 재학생 설문 응답에서 유도하고 나머지는 주로 연구자가 학사 행정 범위와 알려진 실패 유형을 포함하도록 작성했다. Q026은 의도적인 거절 시험 후보로 포함했다. 질문 유형은 사실, 절차, 일정, 연락처와 정책을 포함한다. 최종 평가 정답표의 기대 행동은 완전 답변 28문항, 제한 답변 3문항과 거절 19문항이다. Q011과 Q035는 같은 질문이므로 50문항 결과를 주 결과로 유지하고 Q035를 제외한 49문항 결과를 민감도 분석으로 병기한다. 질문 집합은 무작위 표본이 아니고 같은 집합의 실패가 시스템 개발에도 사용됐으므로 결과 해석은 이 고정 사례에 한정한다.

### 3.3 분석 단위

- 검색 평가는 질문별 top-5 페이지와 청크를 분석한다.
- 페이지 평가는 질문과 canonical URL의 쌍을 분석한다.
- 근거 평가는 질문과 청크 ID의 쌍을 분석한다.
- 최종 응답 평가는 질문별 첫 번째 정상 운영 응답을 분석한다.
- 반복 진단은 같은 질문의 세 구조화 응답 행동이 일치하는지만 분석한다.

## 4. 시스템과 동결 조건

### 4.1 문서 처리

공식 웹 페이지와 문서를 수집하고 HTML·PDF를 파싱해 텍스트와 표 청크로 나눈다. 검색 입력에는 청크 본문과 함께 문서 제목과 메뉴 경로를 사용한다. 문서와 청크는 PostgreSQL에 저장하고, 활성 문서의 비어 있지 않은 청크를 ChromaDB와 BM25에 색인한다. 의미 검색 벡터는 ChromaDB에, BM25 색인은 별도 파일에 저장한다.

### 4.2 검색 경로

BM25 검색은 한국어 경량 토큰화와 제한된 도메인 동의어 확장을 사용한다. Semantic 검색은 Voyage 임베딩으로 질문 벡터를 만들고 ChromaDB에서 유사 청크를 조회한다. Hybrid 검색은 두 후보 목록을 RRF로 결합하며 RRF 상수는 60이다. RRF 점수는 순위 결정에 사용하고, 의미·BM25 점수의 가중 결합으로 만든 relevance는 evidence gate의 절대 관련도 판정에 사용한다. 상세 질문에서는 제목형 청크 뒤의 표 청크를 보강하고 중복 결과를 제거한다.

### 4.3 근거 선택과 생성

검색 결과는 문서 단위로 묶은 뒤 최대 4개의 evidence 후보로 제한한다. 후보는 relevance가 0.35 이상이거나 질문과 직접 학사 키워드가 하나 이상 겹칠 때 통과한다. 통과 후보가 없으면 백엔드가 근거 부족 응답을 반환한다. 후보가 있으면 운영 프롬프트가 답변 가능 상태, 요약, 절차, 주의·제한과 사용 출처 번호를 구조화된 JSON으로 생성하도록 요청한다. 백엔드는 JSON을 검증·복구하고 실제 사용 번호에 해당하는 출처만 최종 구조화 응답에 표시한다.

### 4.4 검색 비교 조건

검색 비교는 같은 코퍼스에서 BM25-only, Semantic-only와 Hybrid의 검색 경로를 연속 실행한 동결 결과를 사용한다. 각 단일 검색 구성은 해당 검색기만 활성화하고 관련도 결합 가중치를 1.0으로 두며, 상세 컨텍스트 확장과 중복 제거 등 공통 운영 후처리는 유지한다. 큐레이션 고정 결과인 Best Bets만 끄고 검색기 분기를 비교한다. 각 검색기는 내부 후보 20개를 요청하고 최종 반환 결과 중 top-5를 채점한다.

### 4.5 최종 응답 실행 조건

최종 응답 평가는 현재 운영 Hybrid 검색, evidence gate, 운영 프롬프트, Gemini 생성, JSON 검증·복구와 출처 후처리를 그대로 사용한다. 검색 category는 `null`이고 evidence 관련도 결합 가중치는 Semantic 0.7, BM25 0.3이며 두 검색기에서 각각 20개 후보를 요청하고 최대 6개 결과를 반환한다. 최종 응답 실행에서는 운영 동작인 Best Bets를 켠다. LLM은 `gemini-3-flash-preview`, 임베딩은 `voyage-4-large`를 사용했고 provider sampling 값은 별도로 지정하지 않았다. 질문 순서는 고정 시드 `20260715`로 한 번 섞고 같은 순서로 세 바퀴 실행했다. 응답 캐시를 우회해 세 실행이 모두 실제 생성 경로를 거치게 했고, 질문은 순차 실행했다.

### 4.6 코퍼스 동결

최종 응답 실행 전후에 PostgreSQL 문서·청크, Chroma ID 집합과 BM25 파일의 지문을 비교했고 코퍼스가 변하지 않았음을 확인했다. 동결 시점에는 전체 문서 7,608개, 활성 문서 4,087개, 전체 청크 42,206개, 색인 청크 20,788개가 있었다. Chroma 항목은 20,788개였고 BM25 파일은 1개였다. 실행 중에는 크롤, 파싱과 재색인을 수행하지 않았다.

## 5. 최종 평가 정답표

### 5.1 정의

평가 정답표(qrel)는 질문별로 어떤 페이지와 청크가 답을 완전 또는 부분 지지하는지 기록한 판정 집합이다. 최종 정답표는 검색 회수와 최종 응답에 필요한 개념을 다음 세 수준으로 분리한다.

| 수준 | 판정 축 | 역할 |
| --- | --- | --- |
| 질문 | 기대 행동과 주된·부차적 사유 | 완전 답변, 제한 답변, 거절 중 무엇이 필요한지 결정 |
| 페이지 | 지지 정도, 시간 유효성, 대상자 적합성 | 관련 페이지의 내용과 현재 배포 가능성을 분리 |
| 청크 | 근거 강도와 근거 유형 | 실제 검색된 텍스트 또는 페이지 도달이 질문을 지지하는지 판정 |

### 5.2 후보 구성

BM25-only, Semantic-only와 Hybrid 검색의 동결 top-5 합집합에 이전 판정과 예비 최종 응답 평가에서 확인된 양성 seed를 더해 후보 pool을 만들었다. 세 실행의 top-5에 등장한 페이지와 청크는 최종 채점 전에 모두 판정했다. 이 pool은 관찰된 검색 결과를 공정하게 비교하기 위한 것이며 전체 코퍼스의 모든 관련 문서를 망라하는 exhaustive judgment가 아니다. 코퍼스 또는 수집 범위 밖의 목표 출처는 별도 목록에 기록했다.

### 5.3 판정 코드북

페이지 지지는 완전 지지(`full`), 부분 지지(`partial`), 비지지(`invalid`)로 구분한다. 페이지의 시간 유효성은 유효(`current`), 만료(`stale`), 불명(`unknown`)으로, 대상자 적합성은 일치(`match`), 불일치(`mismatch`), 불명(`unknown`)으로 구분한다. 청크 근거는 완전 근거(`full`)와 부분 근거(`partial`)를 양성 라벨로 부여하고, 양성 라벨이 없는 청크를 비지지로 부른다. 페이지의 비지지는 `invalid` 라벨로 기록되고 청크의 비지지는 양성 라벨 부재로 기록된다는 점이 산출물 수준에서 다르다. 근거 유형은 `text_chunk`와 `page_navigation`으로 구분한다. 질문 기대 행동은 완전 답변(`full_answer`), 제한 답변(`qualified_answer`), 거절(`abstain`)으로 구분한다. 완전 답변 이외의 주된 사유는 필수 주장 부족(`missing_required_claim`), 수집 실패(`acquisition_failure`), 시점 만료(`stale`), 판정 pool 내 근거 부재(`absent`), 대상자 불일치(`audience_mismatch`), 개인화(`personalized`), 정책 제외(`policy_exclusion`)의 일곱 가지이며, 확정된 50문항에서 실제로 관찰된 주된 사유는 앞의 다섯 가지다.
기대 행동은 시스템의 보수적 배포 가능성을 감사하기 위해 연구자가 사전 정의한 정책 라벨이며, 대학이 승인한 상담 정책이나 사용자 선호를 대표하지 않는다. 따라서 행동 불일치는 오답률이 아니라 이 정책 기준과의 불일치로 해석한다.
페이지의 시간 유효성은 문서가 현재 안내에 사용 가능한지(문서 시간 배포 가능성)를 판정하는 축이고, 최종 응답 rubric의 시간 축은 응답이 실제로 말한 시간 민감 주장이 유효한지(응답 주장 시간 유효성)를 판정하는 별개 축이다. 문서 수준 시점 만료 때문에 거절이 기대되는 문항이라도 응답이 시간 민감 주장을 하지 않으면 응답 축은 해당 없음일 수 있으며, 이 경우 내용·배포 축을 통과하고도 정책 불일치만 남는 응답이 가능하다.

### 5.4 초벌과 사람 감사

고정 코드북으로 50문항의 후보 전량에 LLM 초벌 판정을 생성하고 초벌 JSON을 먼저 동결했다. Claude (Fable 5)가 12문항, Codex (GPT 5.6 Sol)가 38문항을 나누어 판정했다. 사람 검토자는 초기 라벨, 선정 사유, 검색 방식, 순위와 점수를 보지 않은 상태에서 페이지 정보와 청크 전문을 확인해 질문–페이지 묶음을 판정했다. 사람 감사 범위는 사전 정의한 고위험 표적 67묶음과 양성·음성 층화 표본 20묶음 등 총 87묶음이다. 층화 표본은 감사 계획에 기록한 고정 시드로 추출했다.

### 5.5 감사 결과와 조정

판정은 세 단계로 진행했다: LLM 초벌 판정, 초기 라벨을 가린 단일 저자 재판정, 라벨 공개 후 같은 저자의 최종 조정이다. 재판정 단계는 초기 라벨 비공개 사람 감사이지만, 최종 조정은 초기 라벨을 본 상태의 결정이므로 blind 결정이 아니다.
조정 전 원시 차이는 표적 67묶음에서 페이지 43건과 evidence grade 34건, 층화 표본 20묶음에서 페이지 7건과 evidence grade 7건이었다. 원시 차이는 사람 재판정과 초벌 라벨의 최초 불일치 수이며 초벌 오류율이나 평가자 간 불일치율이 아니다.
페이지·청크 감사 차이는 코드북에 따라 조정했고 최종 결정은 저자가 내렸다. 이어서 질문 50개의 기대 행동과 사유를 사람이 전량 확인했다. 이 질문 수준 검토는 초벌 제안을 표시한 저자 확인 절차였다. 초벌 대비 최종 채택 변경은 페이지 3쌍, 청크 근거 4쌍, 질문 기대 행동 2건과 부차 사유 1건이었다. 원시 차이 중 초벌 라벨을 유지한 개별 근거는 변경 채택 건 중심으로 기록됐다.
이 절차는 표적·표본이 위험 기반 선택 표본이므로 전체 qrel 정확도나 평가자 간 신뢰도를 추정하지 않는다. 절차 명칭은 `LLM 초벌·단일 저자 감사 및 조정 qrel`로 쓰고, `human-verified`나 `독립 사람 판정`으로 부르지 않는다.

### 5.6 발행 결과

최종 발행본은 페이지 424행, 청크 근거 626행과 질문 판정 50행이다. 목표 출처 목록에는 수집 실패 관련 5행이 있다. 페이지 판정은 완전 지지 74행, 부분 지지 109행, 비지지 241행이다. 청크 판정은 완전 근거 78행, 부분 근거 128행, 비지지 420행이며, 양성 근거 206행은 text chunk 197행과 page navigation 9행으로 나뉜다. 질문 수준의 pool support는 완전(`full`) 35문항, 부분(`partial`) 10문항, 없음(`none`) 5문항이다. 최종 질문 기대 행동은 완전 답변 28문항, 제한 답변 3문항, 거절 19문항이다.

### 5.7 발행 검증

발행 직후 12개 invariant를 통과했으며, 세 검색 실행의 top-5에 미판정 후보가 없음을 확인했다.

## 6. 검색 평가

### 6.1 지표

`PageHit full@5`는 완전 지지 페이지가 top-5에 하나 이상 있는 질문 비율이다. `PageHit any@5`는 완전 또는 부분 지지 페이지가 top-5에 하나 이상 있는 질문 비율이다. `nDCG support@5`는 페이지 지지를 완전 지지 2, 부분 지지 1, 비지지 0으로 두고 같은 URL의 첫 청크에만 gain을 주는 순위 품질이다. `nDCG deployable@5`는 시간 유효성이 유효이고 대상자가 일치인 페이지에만 지지 gain을 주는 순위 품질이다. `EvidenceHit full@5`와 `EvidenceHit any@5`는 text chunk 근거의 완전 또는 부분 회수를 측정한다. 페이지 위치 자체가 답인 navigation 질문은 text evidence 분모에서 제외한다.

### 6.2 분모

- 지지 페이지가 있는 질문은 45개다.
- 현재 배포 가능한 페이지가 있는 질문은 39개다.
- text chunk 근거로 평가하는 질문은 38개다.
- Q035를 제외하면 각 분모는 44개, 38개, 37개가 된다.

### 6.3 RQ1 결과

| 검색 구성 | PageHit full@5, N=45 | PageHit any@5, N=45 | nDCG support@5, N=45 | nDCG deployable@5, N=39 | EvidenceHit full@5, N=38 | EvidenceHit any@5, N=38 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25-only | 0.3556 (16/45) | 0.6000 (27/45) | 0.3104 | 0.3138 | 0.2895 (11/38) | 0.6316 (24/38) |
| Semantic-only | 0.7111 (32/45) | 1.0000 (45/45) | 0.8216 | 0.7264 | 0.7105 (27/38) | 1.0000 (38/38) |
| Hybrid | 0.7333 (33/45) | 0.9778 (44/45) | 0.7023 | 0.6560 | 0.7368 (28/38) | 0.9737 (37/38) |

Hybrid는 Semantic보다 완전 페이지와 완전 text evidence를 각각 한 문항 더 회수했다. Semantic은 부분 지지를 포함한 페이지·근거 회수와 두 nDCG에서 Hybrid보다 높았다. Hybrid가 Semantic에 비해 완전 근거 hit를 추가한 유일한 문항은 Q005였고, 그 후보는 BM25가 제공했다. 이 페이지는 시점이 만료돼 최종 기대 행동이 거절이므로 완전 지지 페이지 회수가 곧 배포 가능한 답을 뜻하지는 않는다. Semantic만 부분 지지를 포함한 페이지를 회수한 대표 문항은 Q024이며, Hybrid에서는 BM25의 비관련 결과가 합쳐지면서 해당 페이지가 top-5 밖으로 밀렸다. Q024의 부분 지지 페이지에도 핵심 주장이 없어 최종 기대 행동은 수집 실패에 따른 거절이다. 이 결과에서는 완전 근거의 최소 한 건 회수와 전체 관련 근거의 순위 품질 사이 trade-off가 관찰됐다.

### 6.4 중복 민감도

Q035를 제외한 49문항 분석에서도 모든 지표의 검색 구성 순위가 유지됐다. 50문항 결과와 비교한 값의 절대 변화는 BM25-only `EvidenceHit full@5`에서 최대 0.0192였다. 50문항을 주 결과로 유지하고 49문항 결과는 중복 민감도 확인으로만 병기한다.

### 6.5 감사 전후 민감도

같은 동결 검색 결과를 LLM 초벌 정답표와 사람 조정 최종 정답표로 각각 채점했다. 두 판정의 page support, deployable page와 text evidence 대상 질문 집합은 각각 45, 39, 38문항으로 같았다. 6개 지표 모두 검색 구성 순위가 유지됐다. 50문항에서 최대 절대 변화는 Semantic-only의 `EvidenceHit full@5` 0.052632였고, Q035를 제외한 분석에서는 0.054054였다. 이는 최종 채택된 qrel 조정 범위에 대한 민감도 분석이며, 최종 qrel이 참임을 검증하는 것이 아니라 조정이 RQ1의 질적 결론을 뒤집지 않았다는 제한적 강건성만 보여준다.

### 6.6 논문 서술안

> 이 동결 검색 실행에서는 지표별 최고 구성이 서로 달랐다. Hybrid는 완전 지지 페이지와 text evidence를 하나 이상 회수한 비율이 가장 높았으나 그 차이는 각각 한 문항 규모였고, Semantic은 부분 지지를 포함한 회수율과 지지·배포 적합성 nDCG에서 가장 높았다. Q005와 Q024에서는 BM25 후보의 결합 여부에 따라 최종 top-5 구성이 달랐다.

### 6.7 집필 통제

- 세 구성을 `알고리즘 자체`가 아니라 공통 후처리를 공유하는 검색 경로 구성으로 설명한다.
- Best Bets만 끄고 공통 운영 후처리를 유지한 검색 경로 비교임을 방법 절에 명시한다.
- `Hybrid가 가장 좋다`, `Semantic이 가장 좋다`, `검색 성능을 개선했다`고 단정하지 않는다.
- qrel의 판정 범위와 gain 정의가 다른 과거 Recall·MRR 수치와 v4 지표를 직접 증감 비교하지 않는다.
- 작은 목적 표집에서 통계적 유의성을 주장하지 않는다.

## 7. 최종 응답 평가

### 7.1 목적

최종 응답 평가는 현재 운영 Hybrid 구성의 첫 정상 구조화 응답을 대상으로 하며, 최종 API 응답의 답변 텍스트와 표시 출처를 재현한 통제 평가 화면에서 판정한다. 브라우저 UI 배치, 상태 배지, 링크 클릭과 후속 대화는 평가 범위가 아니다. 응답 행동, 내용 정확성, 실제 주입 근거 지지, 출처 표시, 시간·대상자·개인정보 적합성을 분리해 관찰한다. 판정 값은 본문에서 한국어로 쓰며 판정 산출물 필드 값과의 대응은 내용 정확성 완전 정확(`fully_correct`)·부분 정확(`partially_correct`)·부정확(`incorrect`), 실제 주입 근거 지지 완전 지지(`fully_supported`)·부분 지지(`partially_supported`), 표시 출처 완전(`complete`)·부정확(`incorrect`), 시간 유효성 유효(`current`)·만료(`stale`)·불명(`unknown`), 대상자 적합성 일치(`match`)·불일치(`mismatch`)·불명(`unknown`), 개인정보 안전(`safe`)·개인정보 위험(`privacy_risk`)이다. 해당 없음은 모든 품질 축에서 `not_applicable`로 기록된다.

### 7.2 실행

50문항을 같은 고정 순서로 세 바퀴 실행해 150개 정상 응답을 얻었다. 시스템 오류, 평가 수준 재시도와 JSON 복구는 모두 0건이었다. 첫 바퀴 50응답만 사람 본평가에 사용하고 두 번째와 세 번째 바퀴는 최종 파이프라인이 반환한 구조화 행동의 반복 일치도에만 사용했다. 실제 LLM 호출은 144회, embedding 호출은 150회였다. Q024와 Q050은 세 실행 모두 evidence gate를 통과한 근거가 없어 LLM을 호출하지 않았으며, 이 6건을 제외한 144건에서 LLM을 호출했다.

### 7.3 단계별 마스킹 판정

첫 단계에서 질문과 최종 답변 텍스트·표시 출처(통제 화면 재현)만 보고 실제 행동을 판정했다. 기대 행동, 파이프라인의 자체 answerability, 검색 상태, 원시 출력, 주입 evidence와 반복 결과는 화면에서 숨겼다. 첫 단계 50건을 잠근 뒤 실제 주입 evidence와 라벨을 숨긴 최종 정답표 참조 묶음을 공개해 정확성, 근거, 출처와 배포 적합성을 판정했다. 모든 축을 잠근 뒤에만 기대 행동, 파생 성공·오류와 반복 결과를 공개했다. 첫 응답 50건은 단일 저자가 이 단계별 마스킹 절차로 판정했다.

### 7.4 사전 동결과 조정

판정 기준, 실행 프로토콜, 프롬프트, 모델 문자열, qrel, 코퍼스 지문과 실행 원본 해시를 응답 판정 전에 동결했다. 첫 응답 50건의 최종 판정은 단계별 마스킹과 사전 정의한 판정 일관성 점검을 거쳐 확정했고, 조정 이력은 판정 산출물에 기록했다. 모든 판정에는 사전 동결한 성공 기준과 rubric을 적용했다.

### 7.5 엄격한 종합 성공

정상 응답은 다음 조건을 모두 충족할 때만 엄격한 종합 성공이다.

- 기대 행동과 실제 행동이 같다.
- 기권이면 명확한 근거 부족 고지가 있다.
- 내용이 완전 정확하거나 순수 기권으로 해당 없음이다.
- 주장이 실제 주입 evidence에 완전 지지되거나 순수 기권으로 해당 없음이다.
- 표시 출처가 완전하거나 순수 기권으로 해당 없음이다.
- 시간·대상자·개인정보 배포 적합성을 통과한다.

부분 정확과 부분 지지는 엄격한 종합 성공에 포함하지 않고 별도 결과로 남긴다. 여기서 엄격한 종합 성공은 사전 정의된 다축 rubric의 결합 준수, 즉 위 조건을 모두 동시에 충족한 응답의 비율을 뜻하며, 일반 정확도나 실제 사용자 성공률이 아니다.

부분 정확과 부정확을 엄격한 내용 정확성 실패로 세고, 순수 기권의 해당 없음은 실패로 세지 않았다. 세 집합의 교차는 다음과 같다.

Q016과 Q031은 내용 지지가 부분적이어서 실패했고, Q002·Q020·Q033·Q041은 내용 지지는 완전했지만 표시 출처가 부정확해 실패했다. 모델의 답이 주입 근거에 지지되는 것과 그 지지 출처가 올바르게 표시되는 것은 별개 문제라는 직접 사례다. 배포 적합성은 적용 가능한 시간 값이 유효, 대상자 값이 일치, 개인정보가 안전일 때 통과하며 불명도 엄격 기준에서는 실패다. 내용 정확성 실패는 12문항, 나머지 두 축은 각각 6문항이었고 세 축의 교집합은 Q016과 Q031 두 문항이었다. 제한된 교집합은 세 축이 서로 다른 실패 집합을 포착했음을 보여준다.

### 8.3 대표 사례

- Q002는 내용이 완전 정확하고 실제 주입 evidence의 내용 지지도 완전하며 배포 가능했지만 표시 출처가 부정확해 결합 근거 축만 실패했다.
- Q040은 내용과 실제 주입 근거·표시 출처가 맞았지만 지난 회차 정보여서 배포 적합성만 실패했고, 거절 기대와 달리 완전 답변했다.
- Q016은 대학원용 정보를 학부 입학 상담 질문에 적용해 내용, 근거와 대상자 적합성이 함께 실패했고, 제한 답변 기대와 달리 완전 답변했다.
- Q025는 실제 주입 근거와 표시 출처, 배포 적합성은 통과했지만 입학년도·학과별 차이를 특정하지 않은 채 필수과목을 안내해 내용 정확성은 부분 정확으로 판정됐다. 제한 답변 기대와 달리 완전 답변한 행동 오류도 함께 있었다.

### 8.4 논문 서술안

> 엄격한 내용 정확성 실패는 12문항, 결합 근거 축 실패와 배포 적합성 실패는 각각 6문항이었다. 내용 정확성과 결합 근거, 내용 정확성과 배포 적합성의 교집합은 각각 4문항이었고, 세 축을 모두 실패한 문항은 Q016과 Q031뿐이었다. 표시 출처가 부정확해 근거 축만 실패한 사례, 근거에 충실하지만 지난 회차 정보여서 배포 적합성만 실패한 사례와 두 축을 통과하고도 질문의 핵심 내용을 완성하지 못한 사례가 각각 관찰됐다.

### 8.5 집필 통제

- 내용 정확성, 결합 근거 축과 배포 적합성 실패 집합의 차이는 동일한 50문항 안에서 확인한 직접 관찰로 단정할 수 있다.
- 실패 유형의 비율을 전체 대학 질의나 다른 RAG 구성으로 일반화하지 않는다.
- `근거 충실성은 배포 적합성을 보장하지 않았다`는 문장은 본 사례로 한정한다.
- 분해형 평가가 기존 평가보다 일반적으로 정확하다고 주장하지 않는다.

순수 기권 8건은 사실 안내와 표시 출처가 없어 정확성·근거·출처 축을 해당 없음으로 판정했다. 기권 응답에 사실·연락처·경로가 포함되면 해당 주장에는 모든 품질 축을 적용했다. 시간 유효성의 해당 없음 40건은 응답 주장 시간 유효성 축의 값이며, 문서 수준 시간 배포 가능성과 별개다(§5.3). 문서 시점 만료로 거절이 기대되는 문항에서 응답이 시간 민감 주장 없이 절차만 안내하면 이 축은 해당 없음이 되고, 그 불일치는 행동 축(정책 불일치)에서 포착된다.

### 9.4 반복 진단

최종 파이프라인의 구조화된 응답 행동은 46/50(92.0%)에서 세 번 모두 같았다. 행동이 달라진 문항은 Q008, Q029, Q039와 Q041이다. 이 결과는 파이프라인이 반환한 `answerable`, `partial`, `insufficient` 범주의 반복 일치도이며, Q024와 Q050은 LLM 호출 없이 evidence gate에서 `insufficient`를 반환했다. 두 번째와 세 번째 응답은 내용 정확성·근거·배포 적합성 판정 대상에 포함하지 않았으므로 46/50은 구조화 행동의 반복 진단 결과로 한정한다. 이 시스템 필드 범주는 사람이 응답 텍스트를 보고 코딩한 실제 행동(§9.2)과 다른 변수이므로, 46/50을 사람 판정 행동의 반복 검증이나 답변 내용의 안정성으로 해석하지 않는다.

### 9.5 논문 서술안

> 엄격한 종합 기준에서 50문항 중 31문항이 기대 행동, 내용 정확성, 실제 주입 근거, 표시 출처와 배포 적합성을 모두 충족했다. 완전 답변 기대 문항은 22/28이 성공한 반면 제한 답변과 거절 기대 문항은 각각 1/3과 8/19였다. 과잉답변은 13/22에서 관찰됐고 과잉거절은 0/31이어서, 본 구성의 행동 오류는 필요한 답변을 포기하기보다 제한하거나 거절해야 할 질문에 답하는 방향으로 나타났다.

### 9.6 집필 통제

- 31/50은 `엄격한 종합 성공`으로 보고하고 일반 정확도, 성능과 배포 합격률을 구분한다.
- 1/3은 제한 답변 기대 문항 세 건에서 관찰된 결과로 한정한다.
- 과잉답변과 과잉거절은 각각의 분모를 함께 명시한다.
- 46/50은 구조화 행동 범주의 반복 일치로 보고한다.
- 절대 성공 건수와 무관하게 사전 동결한 rubric을 일관되게 적용한다.

## 10. 종합 논의

### 10.1 축의 경험적 분리

검색 회수 지표와 최종 응답 품질은 서로 다른 실행 조건과 분모에 따라 독립적으로 보고한다. 검색 평가는 구성 사이의 회수·순위 trade-off를 다룬다. 동일한 첫 응답 50건 안에서는 내용 정확성, 결합 근거 축, 배포 적합성과 행동 오류의 실패 집합 차이와 각 축이 포착한 오류의 성격을 설명한다.

### 10.2 검색 구성의 trade-off

이 동결 실행에서 Hybrid는 완전 근거 회수가 한 문항 높았고 Semantic은 전체 관련 근거의 순위 품질이 높았다. 해당 문항(Q005, Q024)에서는 BM25 후보의 결합 여부와 최종 순위가 구성마다 달랐으며, 이를 융합의 일반적 기제나 인과 효과로 해석하지 않는다. 생성 단계가 여러 evidence 후보를 받는 현재 설계에서는 완전 근거의 최소 한 건 회수가 중요할 수 있다. 이번 검색 구성 비교는 검색 지표까지를 분석 범위로 삼았으며, RQ1은 Best Bets를 끈 top-5 비교이고 최종 응답은 Best Bets를 켠 top-6 실행이므로 두 실험을 인과로 연결하지 않는다. 검색 구성별 최종 응답 품질 비교는 후속 연구 과제로 남는다.

### 10.3 과잉답변

이 문항셋에서 최종 운영 파이프라인은 완전 답변이 필요한 문항을 거절하지 않았고, 필수 주장이 부족하거나 수집·시점·대상 문제로 제한 또는 거절이 필요한 22문항 중 13문항에서 답변을 시도했다. 13문항 중 3문항은 내용·근거·배포 축을 모두 통과한 정책 전용 불일치였고 10문항은 품질 축 실패를 동반했다. 즉 과잉답변의 상당수는 틀린 답이 아니라 보수적 정책이 요구한 제한·거절을 하지 않은 행동이며, 이를 정확성·근거성·배포 적합성과 별도의 행동 축으로 보고한다. 이 빈도는 목적 표집 감사 문항셋의 결과이며 실제 서비스 질의 분포의 과잉답변률을 추정하지 않는다.

### 10.4 평가 설계의 의미

분해형 평가는 서로 다른 실패 원인을 각각 기록하는 방식이다. 본 연구는 이 절차를 한 사례에 구성·적용했으며 다른 기관과 구성에서의 재현성과 평가자 신뢰도는 후속 검증 과제로 남는다.

## 11. 한계와 타당성 위협

### 11.1 외적 타당성

단일 대학, 단일 한국어 공식 문서 도메인과 목적 표집 50문항을 사용했다. 질문 분포가 실제 사용자 로그를 대표하지 않으며 실사용자 만족도, 탐색 시간과 업무 성공을 측정하지 않았다. 결과의 빈도와 비율을 다른 대학, 언어, 모델 또는 서비스로 일반화할 수 없다.

### 11.2 평가 정답표

최종 정답표는 세 검색 구성의 top-5와 기존 양성 seed를 이용한 pooled judgment다. 전체 코퍼스의 모든 관련 문서를 판정하지 않았으며 세 구성 모두 회수하지 못하고 seed에도 없는 문서는 pool에 없을 수 있다. LLM이 후보 전량의 초벌을 만들고 단일 저자가 위험 기반 표적·표본 감사를 수행했으므로 독립적인 사람 전량 이중판정이 아니다. 사람 감사 표본으로 전체 라벨 오류율이나 평가자 간 일치도를 추정하지 않는다.

### 11.3 평가 개발의 순환성

같은 질문 집합의 초기 실패와 사례 검토가 코퍼스·검색 구현과 최종 평가 설계의 개선에 사용됐다. 최종 지표는 동결된 qrel과 검색 결과로 재산출했지만 완전히 독립적인 미사용 테스트셋은 아니다. 본 결과는 독립 일반화 성능이 아니라 개발된 시스템에 대한 고정 사례 감사로 해석한다.

### 11.4 검색 비교

BM25-only, Semantic-only와 Hybrid는 공통 운영 코드 경로를 사용하지만 순수 알고리즘 구현만을 격리한 이론적 비교가 아니다. 검색은 한 번씩 동결한 실행을 오프라인 채점했으며 실행 변동의 분포를 추정하지 않았다. 작은 분모에서 한 문항이 비율에 미치는 영향이 크므로 통계적 우월성을 주장하지 않는다.

### 11.5 최종 응답 평가

한 LLM 모델 문자열, 운영 프롬프트와 provider 기본 sampling 값 미지정 조건에서 실행했다. 첫 바퀴 50응답은 단계별 마스킹과 판정 일관성 점검을 거쳐 단일 저자가 판정했으며 독립 평가자 간 일치도를 측정하지 않았다. 판정은 실제 브라우저 UI가 아니라 응답 텍스트·표시 출처를 재현한 통제 화면에서 이뤄졌고 상태 배지·화면 배치·후속 상호작용은 평가하지 않았다. 같은 저자가 전날 qrel 기대 행동을 초벌 제안이 보이는 상태에서 확정했으므로 기억과 역할 중첩이 남아 있다. 세 바퀴 중 첫 응답만 전체 품질을 판정했으므로 내용 안정성은 측정하지 않았다. 최종 응답의 운영 검색은 Best Bets를 켠 top-6이고 qrel pool은 Best Bets를 끈 세 검색 구성의 top-5를 중심으로 만들었기 때문에 두 범위가 완전히 같지 않다. 첫 응답의 실제 주입 context 155행 가운데 Q010과 Q049에는 각각 qrel 미판정 페이지 1쌍과 청크 1개가 있어 합계 페이지 2쌍과 청크 2개가 미판정이었다. 판정 기준은 내용 정확성을 동결 qrel 참조 묶음으로, claim support를 실제 주입 evidence로 판단하도록 사전에 고정했지만, 이 두 미판정 후보는 최종 응답 평가와 검색용 qrel의 범위 차이라는 한계로 남는다.

### 11.6 시간 민감성

학사 공지와 일정은 빠르게 바뀌며 평가는 2026-07-14 정답표와 2026-07-15 실행 시점에 고정됐다. 같은 질문도 이후 크롤과 공지 갱신으로 기대 행동과 결과가 달라질 수 있다. 코퍼스와 평가 산출물의 해시를 보존하지만 결과를 현재 서비스 상태로 계속 일반화하지 않는다.

### 11.7 개인정보 진단

첫 응답 50건은 모두 개인정보 축에서 안전으로 판정됐다. 판정된 개인정보 위험 응답이 0건이므로 이 문항셋으로는 개인정보 위험 탐지 성능 자체를 평가하지 못했다. 세 바퀴 전체를 담은 비공개 raw 파일의 자동 검사에서는 전화번호 형태가 11회 검출됐다. 첫 바퀴 raw 출력 50건의 별도 사람 진단에서는 47응답에 민감 패턴이 없고 3응답은 공개된 기관 연락처 등 비개인 정보로 판정돼 개인정보 위험은 0건이었다. 이 결과는 해당 실행에서 식별된 패턴에 한정되며 시스템이 원칙적으로 개인정보를 생성하지 않는다는 보장은 아니다.

### 11.8 미평가 범위

이번 연구의 평가 범위는 세 검색 구성의 오프라인 검색 지표와 운영 Hybrid 구성의 최종 응답이다. 검색 구성별 최종 응답 비교, 실제 사용자 연구, 온라인 로그, 다기관 평가, freshness 기능의 인과 효과, conflict 기능의 정확도와 새로운 거절 정책 평가는 후속 과제로 남는다.

### 13.1 신규성 위협과 기여 문구 함의

- 관련 연구 절의 신규성 경계선은 세 단으로 구성한다: UAEval4RAG(미응답 유형·허용 응답 평가) → MTRAG 계열(answerability-aware 다단계 평가) → 본 연구(대학 행정의 배포 정책·근거 계보·표시 출처를 한 사례 감사로 연결).
- 가장 큰 위협은 축 4의 MTRAG 계열이다. MTRAG(TACL 2025)는 질문을 answerable/partially answerable/unanswerable로 구분하고 응답의 IDK 여부를 판정하며, MTRAGEval(SemEval 2026)은 underspecified 질문의 clarification까지 추가한다. 따라서 "RAG에서 완전·부분·거절 행동을 구분하거나 기대 answerability와 실제 생성을 대조한 최초 연구"라는 주장은 방어할 수 없다.
- 그러나 동일 평가 설계는 아니다. MTRAG 계열의 주 채점은 answerable과 partial 문항을 같은 답변 측으로 묶으므로, 본 연구처럼 full_answer/qualified_answer/abstain의 정확한 3단계 기대·실제 일치를 독립 채점하는 구조는 확인한 문헌에 없다.
- 축 1의 lexical–dense 상보성, zero-shot hybrid 이득, in-domain fusion 손해 가능성, RRF 파라미터 민감성은 모두 선행 결과다. RQ1은 새 fusion 원리나 보편적 우월성을 주장할 수 없고 동일 운영 조건의 대학 행정 코퍼스에서 관찰한 coverage–ranking trade-off로 서술한다.
- 축 7의 pooled qrel, LLM 초벌, 사람의 표적·표본 검증도 새 방법이 아니다. 판정 절차는 방법론 기여가 아니라 제한된 pool에서의 보수적 사례연구 절차로 방어한다.
- 축 2·3·5·6에서는 정면 충돌이 없다. 특히 audience(문서의 대상 집단) 축을 관련성 판정에 분리해 넣은 학술 선례는 미발견이라, temporal은 선행(SituatedQA·FreshQA·HoH)에 접속하고 audience는 본 도메인의 요구(학과 미러·회차 공지·집단별 안내)에서 도출한 신설 축으로 서술한다.
- 확인한 문헌 중 페이지 회수·내용 정확성·근거·시간/대상자 적합성·기대 응답 행동을 한 기관 행정 RAG에서 함께 분해한 동일 연구는 없었다.
- MTRAG·MTRAGEval 독해는 외부 리뷰([20](20-external-review-2026-07-16.md))가 원문으로 독립 확인했으므로 집필 시 재검증이 필요 없다.

## 15. 집필 통제

### 15.1 허용되는 핵심 문장

> 본 사례에서 내용 정확성, 결합 근거 축과 배포 적합성 실패는 동일한 문항 집합으로 나타나지 않았다.

> 본 사례의 검색 비교에서는 완전 근거 회수와 전체 관련 근거의 순위 품질 사이 trade-off가 관찰됐다.

> 현재 구성의 행동 오류는 필요한 답변을 거절하기보다 제한하거나 거절해야 할 질문에 답하는 방향으로 관찰됐다.

> 기존 평가 개념을 연결한 분해형 감사 절차를 한 공식 학사 문서 RAG 사례에 적용했다.

### 15.2 금지되는 문장

- Hybrid는 가장 우수한 검색기다.
- 본 시스템은 58%의 정확도를 달성했다.
- 대학 RAG는 일반적으로 과잉답변한다.
- 분해형 평가가 기존 평가보다 정확함을 입증했다.
- qrel은 전체 코퍼스의 모든 정답을 포함한다.
- 사람 2인이 후보 전량을 독립 판정했다.
- 구조화 행동 92% 일치는 답변 내용이 안정적임을 뜻한다.
- 사람 감사로 검색 성능이 개선됐다.
- 실제 사용자 환경에서 안전성과 유용성이 검증됐다.
- RQ1의 검색 차이가 최종 응답 실패의 원인이다.
- 본 연구는 fully reproducible하다.
- 제한 답변 기대 문항에서 성능이 낮다(세 문항의 사례 결과로만 기술).
- 과잉답변률이 높아 시스템이 위험하다(정책 불일치와 실질 실패를 구분해 기술).

### 15.3 용어

- 첫 등장에서는 `평가 정답표(qrel)`로 설명하고 본문에서는 `최종 평가 정답표` 또는 `분해형 qrel`을 사용한다.
- 내부 버전명 `v4`는 재현 산출물과 계보를 설명할 때만 사용한다.
- `Vector` 대신 구현과 문헌에 맞춰 `Semantic` 또는 `dense retrieval` 중 하나를 선택해 일관되게 쓴다.
- `performance improvement` 대신 `관찰된 차이`, `trade-off`, `오류 유형`을 사용한다.
- `accuracy 62%` 대신 `엄격한 종합 성공 31/50(62.0%)`을 사용한다.
- `independent blind judgment` 대신 `초기 라벨 비공개 사람 감사`를 사용한다.
- `과잉답변`은 첫 등장에서 `사전 정의한 보수적 응답 정책과의 불일치`로 정의하고, 필요 시 정책 전용 불일치와 실질 실패를 구분한다.
- 문서 축은 `시간 배포 가능성`, 응답 축은 `응답 주장 시간 유효성`으로 구분해 부른다(§5.3).
- 사람이 코딩한 `실제 행동`과 시스템이 반환한 `answerability 필드`를 같은 변수로 부르지 않는다.
- `사용자가 받는 응답` 대신 `통제 평가 화면에서 재현한 응답 텍스트와 표시 출처`를 사용한다.
- `재현성 제공` 대신 `산출물 수준 감사 지원`을 사용한다.
- 판정 라벨은 본문에서 한국어로 쓰고, 산출물 enum과의 대응은 §5.3과 §7.1의 괄호 병기를 정본으로 한다.
- 페이지의 `비지지`는 `invalid` 라벨, 청크의 `비지지`는 양성 라벨 부재를 뜻한다(§5.3).

## 17. 재현성과 산출물

### 17.1 정답표 계보

- 초기 판정, 사람 감사, 질문 수준 검토와 최종 조정본을 서로 다른 파일로 보존한다.

- invariant 검사와 scorer는 top-5 미판정 후보가 있으면 실패한다.

### 17.2 검색 결과 계보

- 2026-07-12에 동결한 세 검색 JSONL을 다시 실행하지 않고 최종 정답표로 오프라인 채점했다.
- 50문항과 Q035 제외 49문항을 같은 scorer에서 생성한다.
- 감사 전후 비교는 같은 검색 결과에 다른 판정만 적용한다.
- qrel manifest는 검색 출력과 판정·발행 파일의 해시를 고정한다. 검색 실행 당시 Git 커밋, 코퍼스 지문과 전체 환경은 별도 run manifest로 보존되지 않았다.
- 세 검색 JSONL과 최종 재채점·감사 전후 비교 결과는 로컬 `eval/results/`에 보존돼 있다. 이 디렉터리는 Git에서 무시되므로 공개 저장소에는 일부 입력 해시만 남아 있다.
- 보존된 로컬 JSONL이 있는 환경에서는 오프라인 재채점이 가능하다. 현재 공개 저장소가 지원하는 재현 범위는 산출물 해시 검증이며, RQ1 재채점과 당시 검색 실행의 완전한 재생에는 로컬 입력과 추가 실행 환경 정보가 필요하다.

### 17.3 최종 응답 계보

- 실행 Git 커밋, 질문·qrel·rubric·prompt 해시, 모델·패키지와 호출 설정을 manifest에 기록한다.
- 원시 LLM 출력과 실제 주입 evidence는 비공개 로컬 증거로 보존한다.
- 공개 응답은 개인정보 패턴을 마스킹하고 원시 출력과 evidence 전문을 제외한다.
- 공개 판정과 결과 JSON은 비공개 조정본 해시를 참조하며, 요약 CSV(`eval/exp07-results.csv`)는 집계 행 전용 스키마라 계보 메타데이터를 담지 않는다.
