**상태: 역사 자료.**
**작성일 2026-07-08.**

외부 리뷰와 당시 수용 판단을 보존하며, 현행 논문 방향과 결과는 `19-paper-master.md`를 따른다.

출처: GPT Pro가 저장소 문서·코드·평가 로그를 검토한 독립 리뷰.
성격: [05-scope-and-positioning.md](05-scope-and-positioning.md)의 3자 논의(7/05)를 외부에서 재검증하고 일부를 더 날카롭게 수정한 것. 05를 대체하지 않고 보강한다.

리뷰어는 `.data` DB·ChromaDB·임베딩 API를 재실행하지 않고, 저장소에 기록된 실험 결과·구현 상태만 검토했다. 따라서 아래는 "재측정"이 아니라 "기록 검토 판단"이다.

## 0. 한 줄 결론

Pro 리뷰의 핵심 수정이다.

05의 방향("응용/경험 논문으로 간다")에는 전면 동의한다. 단 한 가지를 더 강하게 고친다. 이 논문은 "거절을 잘하는 RAG"가 아니라, 검색 성능은 크게 끌어올렸지만 커버리지·어휘 갭·거절 판단에서 어떤 구조적 한계가 남는지를 실측한 응용/경험 논문이다. 즉 거절(abstention)은 성공 기여가 아니라 부정적 결과로 써야 한다. 이 프레이밍이 05보다 한 걸음 더 나아간 지점이다(아래 §3.1).

## 1. 05와 일치·재확인된 것

이 항목은 그대로 유지했다.

Pro가 저장소 근거와 대조해 재확인한 항목. 05의 해당 절을 그대로 간다.

- RRF·하이브리드·doc2query·Best Bets는 전부 기존 기법 → 방법 새로움 주장 금지(05 §1.1)
- "GPT보다 낫다"가 아니라 통제·책임 속성(고정 코퍼스·출처 제한·재현성·거절)으로 승부(05 §1.3)
- 키오스크 자체는 기여 아님, "적용 시나리오"로만(05 §1.4)
- 실패 분석이 무게중심(05 §1.5)
- Best Bets는 순수 검색(0.94)과 큐레이션 포함(1.0)을 나란히 분리 보고(05 §1.6)
- 50문항은 "대규모 벤치마크"가 아니라 소규모 case benchmark로 겸손하게(05 §2.5)
- 최신성·충돌 경고·사용자 실험·답변 품질 자동평가는 8페이지에서 축소/future work(05 §4)

## 2. Pro가 확정 사실로 보지 않은 것

이 항목은 보류했다.

리뷰에 등장했어도 근거가 약해 논문 주장으로 삼지 말라고 못박은 것.

- 답변 생성 품질이 좋다 / 환각을 줄였다: 아직 LLM 출력 평가 없음(검색 단계만 측정)
- 사용자 만족도·탐색 시간 개선: 사람 대상 실험 근거 없음
- 최신성 반영 효과 / 충돌 경고 성능: 측정 결과 아니라 기능/구상 단계
- 우리 시스템은 거절을 잘한다: 실제 로그는 반대(insufficient 18개 중 2개만 거절)
- 맨 LLM 대비 환각 감소를 중심 실험으로: 검색 GPT와 붙으면 약해짐, 보조로만

## 3. Pro가 새로 다듬은 것

### 3.1 거절은 성공이 아니라 한계로

EXP-02 결과(거절 정확도 2/18 = 0.11, insufficient의 89%에서 근거 통과)를 숨기지 말고 그 실패 자체를 기여로 쓴다. 이렇게 쓰면 거짓이다.

> 제안 시스템은 정답 부재 질문을 효과적으로 거절한다.

대신 이렇게 쓴다.

> 정답 부재 18개에서 기존 evidence gate는 89%에서 부적절한 근거를 통과시켰다. 공식 문서 기반 RAG에서 검색 성능과 근거 충분성 판단은 별도 과제임을 보였다.

이게 오히려 더 정직하고 논문답다. 05 §3.1의 프레이밍을 "부정적 결과이자 RQ3의 핵심"으로 한 단계 더 강하게 고정한다.

### 3.2 실패 층과 대응

taxonomy를 나열에서 멈추지 말고 "어느 층에서 고쳐야 하는지"를 보여준다.

| 실패 층 | 의미 | 대응 방향 |
|---|---|---|
| `corpus_missing` | 문서가 코퍼스에 아예 없음 | 크롤 범위·시드 확장 |
| `pool_miss` | 문서는 있는데 후보풀 미진입 | 색인·토큰화·형태소·쿼리 확장 |
| `merge_loss` | 후보풀엔 있는데 병합에서 밀림 | RRF/순위 융합 |
| `ranked_low` | 최종 후보엔 있으나 k위 밖 | 재랭킹·문서 다양화 |

핵심 메시지(05 §2.3 헤드라인 후보와 연결): 검색 실패는 랭킹 튜닝 문제가 아니라 대부분 그 이전 단계(커버리지·후보풀)에서 발생한다.

### 3.3 어휘 갭 부정적 결과

"방학" 사례. 정답 학사일정 페이지에 "방학" 단어가 없고 "하계/동계 계절학기", "개강일" 같은 날짜 라벨로만 존재 → BM25·의미 검색 동시 실패. 해결 시도 다섯 가지 (동의어 추가 / LLM 문서 확장 / 규칙 주입 / 순위 보정 / 후보풀 확대)가 모두 실패.
논문에 이렇게 넣을 후보 문장:

> 표준 쿼리 확장·LLM 문서 확장·규칙 주입·순위 보정·후보풀 확대가 모두 실패한 사례로, 한국어 학사 문서의 어휘 불일치가 단순 랭킹 문제가 아님을 보인다.

"기숙사" 사례. 문서를 수집했는데도 의미 52위/키워드 60위 밖(학생은 "기숙사", 문서는 "생활관"). 커버리지 확보와 검색 도달은 별개라는 RQ2 핵심 문장.

### 3.4 GPT-search 비교는 지능이 아니라 통제로

정면 정확도 비교 대신 속성 축으로 프레이밍(05 §1.3 보강).

| 비교축 | GPT 검색 | Campus Copilot |
|---|---|---|
| 지능·일반성 | 강함 | 약함 |
| 공식 코퍼스 제한 | 보장 어려움 | 가능 |
| 재현 가능 평가 | 어려움 | 가능 |
| 출처 통제 | 불안정 | 공식 문서로 제한 |
| 기관 감사(audit) | 약함 | 강함 |
| 거절 정책 | 보장 어려움 | 설계 가능 |

### 3.5 집필 가드레일

말할 수 있는 것 (저장소 근거 있음):

- 50문항 소규모 학사 QA 평가셋 구축 (`eval/questions.csv`, 32/18 분리)
- 순수 검색 Recall@5 0.94 / MRR 0.78 (1차 0.44/0.34 → 단계별 개선)
- RRF가 가중합의 일부 merge_loss를 줄임
- RRF score와 evidence relevance를 분리(엔지니어링 관찰)
- Best Bets는 검색 품질 아니라 운영 큐레이션으로 분리 보고
- 어휘 갭이 lexical·dense 검색을 동시에 무너뜨린 사례
- insufficient에서 evidence gate가 크게 실패(2/18)

말하면 위험한 것:

- 새 검색 알고리즘 제안 / GPT보다 정확 / 환각 감소 / 답변 품질 우수 / 사용자 만족도 / 최신성 효과 / 충돌 경고 성능 / "거절을 잘한다"

### 3.6 RRF 점수와 evidence relevance

독립 RQ로 세우면 "구현 디테일이라 연구문제 아니다" 반박 위험(Claude 지적과 동일). 시스템/논의 절의 소절 "RRF ranking score와 evidence relevance의 분리"로 둔다.
근거: RRF 점수(0.016~0.03)는 절대 관련도 의미가 없어, 정규화하면 답 없는 질문도 1위가 1.0이 되어 근거가 채워지는 위험. 그래서 relevance를 따로 둔 것.

## 4. 05 미결정 사항에 대한 Pro의 권고

05 §2의 각 항목에 Pro가 준 답.

- §2.2 RQ 3개 vs 4개 → 3개 (RRF 분리는 소절로)
- §2.3 단일 헤드라인 채택 → 채택. "실패는 랭킹이 아니라 그 이전 단계" (§3.2와 연결)
- §2.4 GPT 정면 비교 → 중심축 금지. 맨 LLM은 동기 설명으로만, 검색 GPT 정면 실험은 생략
- §2.5 데이터셋 표현 → 소규모 case benchmark로 겸손하게 (공개 여부는 별도)
- §5 제목 1 vs 2 → 2번 선호 (아래)

### 권고 RQ

세 개를 권고했다.

- RQ1 검색 성능: 코퍼스 정제·색인 개선·RRF·어휘 확장이 검색 성능을 얼마나 개선하는가 (근거: 0.44→0.69→0.81→0.88→0.94)
- RQ2 실패 유형: 남은 실패는 corpus_missing/pool_miss/merge_loss/ranked_low 중 무엇이며, 어휘 불일치가 어떤 구조적 문제를 만드는가 (방학·교양필수·기숙사)
- RQ3 정답 부재와 거절 한계: insufficient는 어떤 커버리지 한계를 드러내며, evidence gate 거절은 어디서 실패하는가 (성공이 아니라 한계로)

### 권고 제목·thesis

제목(1순위): 대학 학사 행정 안내를 위한 공식 문서 기반 RAG 시스템 구축 및 검색 실패 분석. 구현 기여 + 분석 기여 동시, "새 알고리즘"·"거절 성공" 과장 회피.

thesis 후보 문장:

> 공식 문서 기반 RAG에서는 하이브리드 검색 성능보다 문서 커버리지·어휘 불일치· 후보풀 진입·근거 충분성 판단이 신뢰성을 좌우한다. 50문항 평가셋으로 검색 성능 개선과 남은 실패 유형을 실측하고, 정답 부재 질의에서 기존 evidence gate의 한계를 분석한다.

## 5. Pro가 권고한 8페이지 구성

05 §6을 미세 조정한 안이다.

| 분량 | 섹션 | 핵심 |
|---:|---|---|
| 0.8p | 1. 서론 | 정보 산재, grounding 필요, 검색 실패 문제 제기 |
| 0.7p | 2. 관련 연구 | RAG, BM25/dense/hybrid, RRF, grounded QA, RAG evaluation |
| 1.0p | 3. 시스템 | 크롤→파싱→청킹→BM25+벡터→RRF→evidence gate→Best Bets (RRF/relevance 분리 소절) |
| 1.0p | 4. 평가셋 | 50문항, answerable 32 / insufficient 18, gold 라벨 |
| 1.3p | 5. 검색 성능 | 0.44→0.94 단계별 + BM25/vector/hybrid 기준선 + nDCG |
| 1.4p | 6. 실패 분석 | 방학·교양필수·기숙사 + 4단계 taxonomy 분포 |
| 1.0p | 7. insufficient·거절 한계 | 18개 정답 부재, evidence gate 2/18, 왜 어려운지 |
| 0.8p | 8. 결론 | 응용 시스템 + 소규모 평가셋 + 실패 분석 + 한계·future work |

05 §6과 거의 같되, 거절 절을 "출처 통제"가 아니라 "거절 한계"로 명시한 것이 차이.

## 6. 액션 우선순위

7/31 투고를 기준으로 한 Pro 리뷰의 권고다.

1. 지도교수 포지셔닝 확인(05 §2.1): 최우선. "새 알고리즘이 아니라 실패 분석·거절 평가·데이터셋 중심 응용 논문으로 KMMS에 맞나요?"
2. BM25 only / Vector only / Hybrid 기준선 표(05 §3.2): 미측정, 1~2시간
3. nDCG@5 추가(05 §3.3): 구현 부담 소
4. 거절은 "성공"이 아니라 "한계"로 정리(§3.1): 이미 측정됨(EXP-02), 프레이밍만
5. 답변 생성 평가는 시간 남으면만: gold answer·citation·hallucination 라벨 필요, 부족하면 과감히 future work

### 거절 개선

선택 과제이며, 새 방법이 꼭 필요할 때 검토할 수 있는 현실적인 카드로 제안됐다.

EXP-03 분석대로 overlap fallback을 원 의미 유사도 하한으로 교체하면 거절이 2/18 → 약 10/18로 늘 수 있으나 answerable 과잉거절이 0 → 3/32 생길 수 있다(미착수). 단 N=50 threshold 튜닝은 검증셋 없이는 과적합처럼 보일 위험이 있어, 넣더라도 보조 결과로만. 논문 중심축은 어디까지나 검색 실패 분석.
