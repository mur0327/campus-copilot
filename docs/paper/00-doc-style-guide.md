# 논문 문서 형식 규칙

docs/paper/ 아래 문서를 쓰거나 고칠 때 지키는 마크다운 형식 규칙이다. 2026-07-08 세션에서 05·07 문서의 형식을 통일하며 초안을 만들었고(당시 적용 과정은 [../sessions/paper-doc-formatting-and-progress-review.md](../sessions/paper-doc-formatting-and-progress-review.md)), 2026-07-16에 §3·§7·§8·§9를 개정해 08·10~16 전체에 적용했다. 이 파일이 규칙의 정본이다.

원칙은 하나다: 장치(인용문·표·볼드·제목 장식)마다 역할을 하나만 준다. 장치가 여러 역할을 겸하면 독자가 마크만 보고 의미를 예측할 수 없게 된다.

## 1. 인용문(>)은 논문 본문 후보 문장에만

강조·결론·각주 목적으로 쓰지 않는다. 인용문 안에는 그대로 논문에 넣을 수도 있는 문장만 담는다.
예: 잠정 초록, thesis 후보 문장, "논문에 이렇게 쓰면 위험한/안전한" 예시 문장. 결론이나 후속 안내는 그냥 문단으로 쓴다.

## 2. 표는 진짜 대조표에만

가로세로 둘 다 의미 있는 경우에만 표로 만든다.
예: 실패층 × 의미 × 대응 방향, 분량 × 섹션 × 내용. "주장 | 보류 이유", "미결정 | 권고"처럼 목록에 가까운 내용은 표로 만들지 않고 목록으로 쓴다.

## 3. 볼드는 문서 상단 상태 라벨에만

문장마다 볼드를 뿌리면 강조가 상쇄된다. 볼드를 허용하는 위치는 문서 상단의 상태·작성일 두 줄뿐이다(§7 참조).

허용되지 않는 볼드:

- 본문 안의 라벨(문제, 대응, 상태, 확정, 수용 등). 라벨은 §8의 평문 패턴을 쓴다.
- 구절 단위 준-강조("가장 위험한 문장" 등)는 평문으로 쓴다.
- 소제목이나 문단 인트로에 볼드 문장을 붙이지 않는다.

예외:

- 용어집 표(04)의 용어 열은 스캔용 라벨이라 볼드 유지.
- 명확한 경고 배너(예: "폐기됨", "invalid") 한 줄은 허용하되 남용 금지.

## 4. 제목은 번호가 계층이면 짧게

`## 3.` `### 3.1`처럼 번호가 이미 계층을 표시하면 제목은 명사로 짧게 쓴다. 이모지, 꼬리표("(결정 필요)" 같은 상태 부기), 부제는 넣지 않는다. 제목 안에는 엠대시(§9)도 넣지 않는다.

## 5. 설명·판단은 평범한 문단으로

박스·표·인용문에 담지 말고 문단으로 쓴다. 장치는 예외적인 경우에 쓰라고 있는 것이지 모든 문장을 담는 그릇이 아니다.

## 6. 줄바꿈은 문장 기준으로

문장을 글자 수에 맞춰 중간에서 강제로 줄바꿈하지 않는다. 문장 끝에서 줄을 바꾸는 것을 기본으로 하되, 의미상 긴밀하게 이어지는 문장은 같은 줄에 둘 수 있다. 목록 항목도 한 문장이면 한 줄에 작성한다.

## 7. 문서 상단 헤더

모든 문서는 H1 제목 아래에 상태와 작성일을 각자 별도 줄에 볼드로 둔다. 그 아래 빈 줄과 부연 설명 문단이 오고, 부연에서 현행 정본(주로 `19-paper-master.md`)을 가리킨다.

```
# 문서 제목

**상태: 역사 자료.**
**작성일 2026-07-10.**

당시 확인한 내용을 보존하며, 현행 방향과 결과는 `19-paper-master.md`를 따른다.

... 이후 본문 ...
```

- 상태와 작성일은 한 줄로 합치지 않는다. 위계가 분리돼야 스캔이 쉽다.
- 문서 안에서 나중에 상태가 바뀐 이력은 별도 문단으로 남긴다. 상단에 두 번째 상태 볼드를 붙이지 않는다(§8의 라벨 패턴 사용).
- 작성일이 원본에 없으면 git 최초 커밋일이나 문서 본문의 최신 작업일을 기준으로 추정해 채운다.

## 8. 본문 라벨은 `라벨: 요약` + 상세

문서 안의 항목 라벨(문제, 대응, 상태, 확정, 수용 등)은 볼드 없이 평문으로 시작한다. 라벨 뒤에는 그 항목을 한 문장으로 압축한 요약을 붙이고, 상세는 다음 줄부터 문단이나 리스트로 이어간다.

```
문제: <한 문장 요약>

<상세 문단 또는 리스트>
```

- 요약이 억지스러우면 그 항목 자체가 정리 안 된 신호다. 원문을 다시 본다.
- 자연스럽게 리스트로 쪼개지는 항목만 리스트로. 억지 리스트는 만들지 않는다.
- 라벨 앞에 번호(1., 2., 3.)를 붙이지 않는다. `라벨: 값` 유연성이 무너지고, 이미 번호가 붙은 상위 섹션(예: W1~W7)과 이중 번호 시스템이 된다.

### 예외: 반복 필드가 5개 이상이면 서브헤딩으로

06 실험 로그처럼 같은 필드 세트가 3회 이상 반복되면 라벨:요약 대신 `#### 필드명` 서브헤딩으로 승격한다. 라벨이 반복되면 스캔이 어렵고, 각 필드가 문단·표·리스트를 포함할 때 서브헤딩이 목차에 자동 등장해 문서 이동이 편해진다.

## 9. 엠대시로 부연 붙이지 않기

엠대시(—)로 문장 안에 부연 설명을 넣지 않는다. 부연은 쉼표, 괄호, 콜론, 별도 문장 중 하나로 처리한다. 표 안의 자리표시자 "—"(값 없음)는 부연이 아니므로 무방하며, 대신 `(없음)` 같은 평문 표기도 허용한다.

권장 대체:

- `설명 — 부연` → `설명(부연)` 또는 `설명. 부연.`
- `A — B이므로 C` → `A. B이므로 C.` 또는 `A(B이므로 C).`
- 리스트 항목의 `라벨 — 값` → `라벨: 값`
