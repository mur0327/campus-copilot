# 단어 사전

**상태: 참고 용어집.**
**작성일 2026-06-25.**

쉬운 설명을 위한 보조 문서이며, 논문에서 사용할 현행 용어와 정의는 `19-paper-master.md`를 우선한다. 표의 용어 볼드는 스캔용 라벨이라 유지한다.

| 단어 | 의미 | 요약 |
| --- | --- | --- |
| **RAG** | 검색한 문서를 바탕으로 LLM이 답변을 생성하는 방식 | “찾아서 답하는 AI” |
| **LLM** | 대규모 언어 모델. ChatGPT, Gemini 같은 생성형 AI 모델 | “답변을 만드는 AI” |
| **크롤링** | 웹사이트의 페이지를 자동으로 수집하는 작업 | “학교 홈페이지 긁어오기” |
| **파싱** | HTML, PDF 등에서 필요한 텍스트와 구조를 뽑아내는 작업 | “문서 내용 해석하기” |
| **청킹** | 긴 문서를 검색하기 좋게 작은 단위로 나누는 작업 | “문서 쪼개기” |
| **임베딩** | 문장이나 문서를 숫자 벡터로 바꾸는 기술 | “글을 숫자로 바꾸기” |
| **벡터 검색** | 의미가 비슷한 문서를 벡터 거리로 찾는 검색 방식 | “뜻이 비슷한 문서 찾기” |
| **BM25** | 키워드 일치도를 기반으로 문서를 찾는 전통적 검색 알고리즘 | “단어가 잘 맞는 문서 찾기” |
| **하이브리드 검색** | 키워드 검색과 벡터 검색을 함께 사용하는 방식 | “단어+의미 검색” |
| **인덱싱** | 문서를 빠르게 검색할 수 있도록 색인을 만드는 작업 | “검색 준비하기” |
| **Vector DB** | 임베딩 벡터를 저장하고 검색하는 데이터베이스 | “의미 검색용 DB” |
| **ChromaDB** | RAG에서 자주 쓰는 오픈소스 벡터 데이터베이스 | “벡터 저장소” |
| **PostgreSQL** | 문서 정보, 로그, 메타데이터 등을 저장하는 관계형 DB | “기본 데이터 저장소” |
| **Redis** | 자주 쓰는 결과를 임시 저장해 빠르게 응답하게 하는 저장소 | “빠른 캐시 저장소” |
| **메타데이터** | 문서의 제목, URL, 수정일, 카테고리 같은 부가 정보 | “문서 설명 정보” |
| **출처 검증** | 답변이 어떤 공식 문서를 근거로 했는지 확인하는 과정 | “근거 있는 답변 확인” |
| **근거 문단** | 답변에 실제로 사용된 원문 일부 | “답변의 증거 문장” |
| **최신성** | 문서가 최근 정보인지, 오래된 정보인지 판단하는 기준 | “최신 정보 여부” |
| **Freshness** | 최신성을 의미하는 영어 표현 | “얼마나 최신인가” |
| **충돌 탐지** | 서로 다른 문서의 날짜, 절차, 조건이 다른지 찾는 기능 | “문서끼리 말이 다른지 확인” |
| **Conflict Warning** | 문서 간 충돌 가능성을 사용자에게 알려주는 경고 | “정보 불일치 경고” |
| **절차 생성** | 여러 문서를 바탕으로 신청 순서나 준비물을 단계별로 정리하는 기능 | “해야 할 일 순서 만들기” |
| **Hallucination** | AI가 근거 없는 내용을 그럴듯하게 지어내는 현상 | “AI의 헛소리” |
| **Grounding** | AI 답변을 실제 문서나 데이터에 근거하게 만드는 것 | “근거 붙이기” |
| **API** | 프론트엔드와 백엔드가 데이터를 주고받는 통로 | “프로그램 간 요청 창구” |
| **FastAPI** | Python 기반 백엔드 API 서버 프레임워크 | “Python 서버 도구” |
| **React** | 사용자 화면을 만드는 프론트엔드 라이브러리 | “화면 만드는 도구” |
| **Tailwind CSS** | 화면 디자인을 빠르게 적용하는 CSS 프레임워크 | “스타일 도구” |
| **프론트엔드** | 사용자가 직접 보는 화면 영역 | “보이는 부분” |
| **백엔드** | 검색, 답변 생성, DB 처리 등 내부 로직 영역 | “뒤에서 처리하는 부분” |
| **Worker** | 크롤링, 파싱, 인덱싱 같은 배치 작업을 처리하는 별도 프로세스 | “자동 수집 담당” |
| **Docker** | 서버, DB, 프론트 등을 컨테이너로 묶어 실행하는 도구 | “실행 환경 포장” |
| **AWS** | 클라우드 서버 서비스 | “인터넷 서버 빌리는 곳” |
| **OCR** | 이미지나 스캔 PDF에서 글자를 인식하는 기술 | “사진 속 글자 읽기” |
| **SSE** | 서버가 답변을 조금씩 실시간으로 보내는 방식 | “타이핑처럼 답변 표시” |
| **Recall@k** | 상위 k개 검색 결과 안에 정답 문서가 있는지 보는 지표 | “정답을 가져왔나?” |
| **MRR** | 첫 번째 정답 문서가 몇 번째에 나왔는지 평가하는 지표 | “정답이 얼마나 빨리 나오나?” |
| **nDCG** | 관련도 높은 문서들이 상위에 잘 배치됐는지 평가하는 지표 | “순위 전체가 좋은가?” |
| **Precision@k** | 상위 k개 검색 결과 중 실제로 관련 있는 문서의 비율 | “가져온 것들이 맞나?” |
| **F1-score** | Precision과 Recall을 함께 고려한 종합 점수 | “정확도와 회수율의 균형” |
| **정답 문서** | 질문에 대한 올바른 근거가 되는 공식 문서 | “진짜 근거 문서” |
| **Gold Dataset** | 사람이 미리 정답을 표시해 둔 평가용 데이터셋 | “채점 기준표” |
| **Baseline** | 성능 비교를 위해 기준으로 삼는 기본 방식 | “비교 기준” |
| **Ablation Study** | 기능을 하나씩 빼보며 성능 차이를 확인하는 실험 | “기능별 효과 검증” |
