# qrel v4 B2 사람 감사 프로토콜

작성일: 2026-07-14. 상태: 사람 감사 시작 전 동결.

이 문서는 [16](16-external-review-2026-07-13.md)의 qrel v4 사람 감사 범위를 대체하는 정본이다.
전량 LLM 초벌은 그대로 보존하되, 사람 검토를 사전 정의된 고위험 묶음의 전수 감사와 나머지 양성·음성 묶음의 층화 표본 감사로 나눈다.
목적은 후보 전량의 사람 이중판정을 주장하는 것이 아니라, 제한된 저자 시간을 EXP-07과 원고 검토에 남기면서 판정 오류가 결과를 바꾸는지를 재현 가능하게 검사하는 것이다.

## 1. 역할과 감사 단위

초벌 전량은 LLM이 고정 코드북으로 판정하고 `eval/qrel-v4-primary-initial.json`에 동결한다.
사람 검토자는 초기 라벨, 선정 사유, 검색 방식, 순위, 점수와 v3 판정을 보지 않은 상태에서 판정한다.
프로젝트와 코드북을 아는 저자이므로 완전한 독립 블라인드 판정이라고 부르지 않고, 초기 라벨 비공개 사람 감사라고 기술한다.

사람 감사 단위는 개별 행이 아니라 질문–페이지 묶음이다.
한 묶음에서 다음을 함께 판정한다.

- 페이지의 support, temporal validity, audience scope
- 그 페이지에서 pool에 들어온 evidence candidate의 지지 여부와 유형
- 본문 부재, 충돌, 결정적 도출, 대상 범위처럼 같은 자료에서 확인되는 쟁점

페이지 묶음을 선택하면 그 페이지의 evidence candidate 판정 컨트롤을 모두 싣는다.
같은 페이지를 page 행과 evidence 행 때문에 반복해서 읽지 않는다.

## 2. 표적 감사

다음 질문–페이지 묶음은 표본 수와 무관하게 전량 감사한다.

- v3→v4에서 페이지 판정 축이 달라진 사례
- 초벌 notes가 `경계:`로 시작하는 페이지 또는 evidence 사례
- temporal 또는 audience 판정이 expected behavior에 영향을 주는 사례
- 문서 간 충돌·상충이 기록된 사례
- invariant 위반 후보
- composition override의 근거로 지정된 사례
- 코드북 §9에서 페이지 행 자체가 사전 쟁점으로 고정된 사례

질문 수준 변경은 §5의 50문항 전량 검토에서 확인한다.
표적 감사 결과는 오류율 추정에 쓰지 않고, 사전 정의된 고위험 사례에서 무엇을 수정했는지만 보고한다.

## 3. 층화 표본

표적 감사에 들지 않은 나머지 묶음에서는 LLM-positive와 LLM-invalid를 모두 표본에 포함한다.
선정은 고정 시드와 질문 ID·canonical URL의 SHA-256 순서를 사용하며, 검토자가 편한 사례를 골라 넣을 수 없게 한다.

주요 층은 다음과 같다.

- LLM 판정: positive / invalid
- 검색 순위: 1–2 / 3–5 / 동결 top-5 밖 seed
- 모드 출현: 단일 모드 / 복수 모드 / seed
- 문서 성격: 일반 페이지 / PDF·이미지 등 특수 문서

질문 유형과 출처 범위는 표본의 다양성을 맞추는 보조 조건으로 사용한다.
모든 조건의 완전한 교차표는 만들지 않는다.
표본 감사는 남은 모집단의 양방향 오류를 탐지하는 품질관리 절차이며, 작은 선택 표본으로 전체 라벨 정확도를 추정하지 않는다.

## 4. 시간 파일럿

최종 표본 수는 행 수만으로 정하지 않는다.
고정 시드 `qrel-v4-b2-20260714`로 양성·음성 및 주요 층을 섞은 10개 묶음을 먼저 판정한다.
초기 라벨과 선정 사유는 공개하지 않고, 묶음별 판정 시간을 기록한다.
불일치를 열기 전에 중앙 시간을 계산해 3~5시간 안에 들어오는 최종 표본 묶음 수를 동결한다.
감사 시트의 묶음 시작·완료 버튼이 개별 시간과 현재 중앙 시간을 계산한다.
파일럿 10개는 최종 감사 표본에 포함한다.

시간 측정 중에는 primary JSON이나 기존 483행 시트를 열지 않는다.
파일럿은 작업량 보정용이며, 결과를 본 뒤 쉬운 묶음만 남기는 필터가 아니다.

## 5. 질문 수준 검토

페이지·evidence 감사와 불일치 조정이 끝난 뒤 50문항의 expected behavior, primary reason, secondary reasons를 사람이 전량 검토한다.
pool support는 최종 page qrel에서 기계적으로 파생하고 수기로 덮어쓰지 않는다.
composition override만 명시된 출처와 근거를 함께 확인한다.

질문 수준 검토는 페이지 표본 감사와 분리한다.
일부 페이지만 제시된 블라인드 시트에서 질문 행동을 먼저 확정하면 보지 못한 페이지의 초벌 판정에 의존하게 되므로, adjudicated page·evidence가 준비된 뒤 별도 시트로 수행한다.

## 6. 불일치와 확대 규칙

다음은 중대한 불일치다.

- `full` 또는 `partial`과 `invalid` 사이 변경
- `full`과 `partial` 사이 변경
- `current`와 `stale` 사이 변경
- `match`와 `mismatch` 사이 변경
- evidence 지지와 비지지 사이 변경
- `full_answer`, `qualified_answer`, `abstain` 사이 변경

notes 표현과 secondary reason 순서만 다르고 결론이 같으면 사소한 차이로 본다.
오류 유형은 결과를 보기 전에 다음 목록으로 고정한다.

- 날짜·시한부 공지
- 학과·대학원 등 대상자 범위
- 위치·확인처 및 페이지 도달형 질문
- PDF·이미지 본문 부재
- 명칭 등가성
- 결정적 산술 도출
- 교차 문서 조합
- 상충 문서
- 개인화·로그인 정보

확대는 다음 순서로 수행한다.

1. 같은 사전 정의 유형에서 중대한 오류가 2건 이상이면 그 유형의 미감사 묶음을 확대한다.
2. 1건이어도 코드북의 체계적 오적용으로 확인되면 그 유형을 확대한다.
3. 서로 독립적인 여러 유형에서 중대한 오류가 나오면 같은 크기의 층화 표본을 한 묶음 추가한다.
4. 여러 층에 걸친 전역적 규칙 오류가 확인될 때만 후보 전량 감사를 검토한다.
5. 감사 전후 검색 방식 순위나 논문의 핵심 결론이 바뀌면 영향을 준 유형을 확대한다.

모든 불일치는 adjudication 기록을 남기고 최종 결정권은 저자에게 있다.

## 7. 보고 계약

표적 감사와 층화 표본 감사를 합친 단일 일치율이나 κ를 보고하지 않는다.
다음을 분리해서 기록한다.

- 표적 감사: 사전 정의 고위험 묶음 수, 중대한 수정 수, 대표 오류 유형
- 층화 표본 감사: 모집단과 고정 시드, 표본 묶음 수, 양방향 중대한 불일치 수, 확대 여부
- 질문 수준 검토: 50문항 검토 완료 여부와 expected behavior 변경 수
- 강건성 확인: 감사 전후 지표, 검색 방식 순위, 헤드라인 결론 변화

감사 대상 선정에 초벌 라벨을 사용하므로 선정 스크립트와 시드는 보존하되, 검토가 끝나기 전에는 행별 선정 사유를 검토자에게 공개하지 않는다.

## 8. 논문 서술

> qrel v4는 세 개의 동결된 production mode가 반환한 top-5 결과의 합집합과 이전 판정에서 확인된 양성 seed를 이용해 pooled 방식으로 구축하였다. LLM이 고정된 코드북에 따라 pooled page 및 evidence 후보 전량의 초기 판정을 생성하였다. 사람 검토자는 사전에 정의한 고위험 질문–페이지 묶음을 전수 검토하고, 나머지 LLM-positive 및 LLM-invalid 묶음에서는 검색 순위, 검색 방식, 출처 범위와 문서 성격을 고려해 고정 시드로 추출한 층화 표본을 초기 라벨과 선정 사유를 보지 않은 상태로 감사하였다. 중대한 불일치가 확인된 유형은 사전에 정한 규칙에 따라 확대 검토하였다. 페이지와 evidence 조정 후 질문 수준의 예상 응답 행동과 사유는 50문항 전량을 사람이 검토하였다. 표적 감사와 층화 표본 감사 결과는 분리해 보고하고, 감사 전후 지표와 검색 방식 순위의 변화를 함께 확인하였다.

한계 절에는 다음을 명시한다.

> 후보 전량에 대한 독립적인 사람 이중판정은 수행하지 않았으므로, v4는 완전 수작업 벤치마크가 아니라 위험 기반 사람 감사를 거친 LLM 보조 pooled qrel이다.

다음 표현은 사용하지 않는다.

- 모든 양성 페이지와 근거를 사람이 검증했다.
- 사람이 후보 전량을 확정했다.
- 독립 2인 판정 또는 교수–저자 κ가 v4 신뢰도를 보장한다.
- 선택 감사로 전체 qrel 정확도를 검증했다.
- pool이 전체 코퍼스의 모든 관련 문서를 포함한다.

## 9. 실행 도구

선정 도구는 `eval/select_v4_audit.py`다. 시간 파일럿 ID는 다음 명령으로 만든다.

```bash
uv run --project backend python eval/select_v4_audit.py \
  --phase pilot --bundle-count 10 \
  --out tmp/qrel-v4/b2-pilot-ids.txt
```

시트는 기존 생성기의 감사 모드로 만들며 `eval/results/` 밖으로 내보내지 않는다.

```bash
uv run --project backend python eval/make_v4_sheet.py \
  --audit tmp/qrel-v4/b2-pilot-ids.txt \
  --out eval/results/qrel-v4-audit-pilot.html
```

최종 표본 묶음 수는 파일럿 중앙 시간을 기록한 뒤 `--phase full`의 `--bundle-count`로 고정한다.
해당 값은 표적 감사 외에 포함할 층화 표본의 총 묶음 수이며, 파일럿 중 비표적 묶음도 이 수에 포함된다.
선정 도구는 파일럿 10묶음이 표적 또는 표본 경로를 통해 최종 감사에 모두 남는지 검사한다.
