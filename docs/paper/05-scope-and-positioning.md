## 0. 한 줄 결론

"GPT보다 낫다"도, "RRF로 새 검색기를 만들었다"도 아니고, 공식 학사 문서 기반
RAG에서 검색 실패·커버리지 한계·거절 가능성을 실측한 **응용/경험 논문**으로 간다.
3자(저자·Claude·GPT) 모두 동의했다.

## 1. 합의된 전제 (확정)

### 1.1 방법론적 새로움은 주장하지 않는다

RRF, 하이브리드 검색, doc2query(문서 확장), Best Bets는 전부 기존 기법이다.
코드에도 RRF 상수 k=60을 원논문 표준값으로 두고 튜닝하지 않는다고 명시돼 있다.

논문에 이런 문장은 위험하다.

> 우리는 하이브리드 검색과 RRF를 통해 기존보다 우수한 새로운 RAG 시스템을 제안한다.

이렇게 쓰면 재발명으로 반려된다. 대신 이렇게 간다.

> 본 연구는 한국 대학 학사 행정 문서라는 제한된 공식 문서 도메인에서 RAG 검색
> 성능을 구축·평가하고, 정답 문서 미검색 원인을 커버리지·후보풀·병합·순위
> 단계로 분해하여 분석한다.

### 1.2 기여는 네 가지 유형으로 놓는다

1. 응용 시스템 — 실 도메인(호남대 공식 문서)에 동작하는 RAG 구축·평가
2. 경험적 분석 — 표준 기법들이 이 도메인에서 어디서·왜 실패하는지 규명
3. 부정적 결과 — 될 줄 알았던 방법(LLM 문서확장 등)이 실패한 원인 규명
4. 도메인 특화 평가 — 라벨된 소규모 학사 QA 평가셋 + 실패 유형 분석

### 1.3 "GPT보다 똑똑하다"는 주장하지 않는다

검색 가능한 GPT는 호남대 페이지를 실제로 찾아온다. raw QA 정확도로는 우리가
더 낫다고 말할 수 없다. 우리 시스템의 장점은 지능이 아니라 통제·책임 속성이다.
고정된 공식 코퍼스, 출처 제한(모든 답이 공식 페이지로 추적), 재현 가능한 평가,
거절(abstention) 정책. "GPT를 이긴다"가 아니라 "감사가능성·통제를 얻는다".

### 1.4 "호남대 특화 + 키오스크" 자체는 기여가 아니다

"우리 학교에 적용했다"만으로는 약하다. 도메인 특화가 기여가 되려면 재사용 가능한
산출물(라벨 평가셋) 또는 일반화되는 발견(실패 유형)이 나와야 한다.

### 1.5 실패 분석이 논문의 무게중심

GPT도 데이터를 주면 분석은 할 수 있으므로 "GPT가 못 한다"는 표현은 쓰지 않는다.
대신 이 프로젝트의 실제 코퍼스·검색 로그·gold label·실패 실험에서만 나오는
재현 가능한 실증 결과로 표현한다. 무게중심은 실패 분석 + insufficient(거절)
평가 + 소규모 벤치마크. 시스템·데이터셋은 이를 뒷받침하는 도구.

### 1.6 Best Bets는 순수 검색과 분리 보고

검색 실패가 증명된 질문에만 큐레이션 고정을 적용하고, 순수 검색 수치(0.94)와
큐레이션 포함 수치(1.0)를 나란히 보고한다. 이 정직성 자체를 논문의 강점으로.

## 2. 미결정 사항

### 2.1 지도교수 확인 — 해소됨 (2026-07-10 확정)

**결과: 승인.** 지도교수와 논의하여 경험/응용/성능분석/실패분석 논문으로 쓰기로
확정했다. 알고리즘 새로움 요구 없음. 별도 스코핑(기관 QA용 거절 정책 같은 작은
방법 기여) 없이 §1의 합의된 전제 그대로 진행한다.

원래 질문이었던 것: 교수님이 "응용/경험 논문이면 된다"고 하면 이 방향으로 충분하고,
"알고리즘 새로움이 하나는 있어야 한다"고 하면 3주 안에 못 맞추므로 별도 스코핑이
필요하다는 갈림길이었다. 전자로 확정되어 아래 §2.2~§2.5는 이 방향 안에서 결정하면
된다.

### 2.2 연구문제(RQ) 최종 세트

넓은 원래 RQ(최신성·출처신뢰도·절차·충돌)는 강한 증거가 없어 축소하기로 함.
후보안 두 가지가 아직 경합 중이다.

GPT 제안 (RQ 4개):

- RQ1. 하이브리드 검색+코퍼스 정제가 검색 성능을 얼마나 개선하는가
- RQ2. 검색 실패는 corpus_missing/pool_miss/merge_loss/ranked_low 중 어떤 유형인가
- RQ3. insufficient 질의는 어떤 커버리지 한계를 드러내며 거절 정책은 왜 필요한가
- RQ4. RRF 순위 융합과 relevance evidence gate 분리의 실용적 의미

Claude 수정 제안 (RQ 3개):

- RQ4를 독립 RQ에서 빼고 시스템/논의 절의 한 소절로 (구현 디테일이라 독립 RQ로
  세우면 "연구문제가 아니다"라는 반박 위험).
- RQ2는 taxonomy 자체가 아니라 실패 유형의 분포(어느 단계가 지배적인가)를 결과로
  밀어야 함 ("그런 단계 구분은 자명하다"는 반박 회피).

미결정: RQ 3개(Claude) vs 4개(GPT). §2.4의 헤드라인 결정과 함께 확정.

### 2.3 단일 헤드라인(thesis) 채택 여부

GPT 개요는 서술적이라 선명한 한 문장 주장이 없다는 지적(Claude). Claude 제안
헤드라인은 논문에 이런 문장으로 넣는 것을 상정한다.

> 공식 문서 RAG의 검색 실패는 순위(ranking) 문제가 아니라 대부분 그 이전 단계
> (커버리지·후보풀)에서 발생한다.

근거는 1차 보고의 "미스 9개 중 8개가 정답이 후보에 아예 없음"이다. 채택하면
RQ2·RQ3가 하나의 주장으로 꿰인다("랭킹 튜닝이 아니라 커버리지·거절이 핵심").

### 2.4 GPT(검색 가능) 정면 비교 실험 여부

GPT 의견은 보조 실험/동기 설명으로는 좋으나 중심축으로는 약함. Claude 의견은
보조 실험조차 리스크(심사위원이 GPT-search를 돌려 잘 되면 논문을 깎음)라서
개념적 동기(출처보증·거절·결정성)로만 언급하고 정면 실험은 생략 권장. 미결정.

### 2.5 데이터셋 공개 범위·표현

50문항은 "대규모 벤치마크"가 아니라 소규모 공개 평가셋 / case benchmark로 겸손하게
표현하기로 합의. 실제 공개(repo 릴리스) 여부와 라이선스, gold URL 포함 여부는
미결정.

## 3. 남은 실험과 보완 항목

GPT 개요는 일부 항목을 "증거 있는 것처럼" 썼으나, 기준선 비교와 nDCG는 아직
안 돌렸다. 거절 실험은 완료됐고, 결과를 성공이 아니라 한계로 프레이밍해야 한다.

### 3.1 거절 실험 — 완료

거절 정확도 2/18 = 0.11. 정답 없는 질문의 89%에서 거절 실패(evidence 게이트가
키워드 겹침만으로 엉뚱한 문서를 통과시킴). answerable 과잉거절 0. "안 되는 쪽"이
나왔고, 이게 오히려 RQ3를 강화하고 작은 방법 기여(보정된 거절 정책)의 동기가 됨.
상세: [06-experiment-log.md](06-experiment-log.md) EXP-02.

후속 미결정: 개선된 거절 정책 설계·측정(미착수), LLM 출력 수준 확인(선택).

### 3.2 검색 기준선 표

BM25 only / Vector only / Hybrid 격리 비교. 현재까지 RRF-vs-가중합, 단계별
개선(0.44→0.94)은 있지만, 투고 체크리스트가 요구하는 단일 검색기 격리 비교표는
아직 없다. 작업량은 harness에 검색기 하나 끄는 모드 추가(--no-best-bets 방식),
1~2시간.

### 3.3 nDCG@k

현재 Recall@5·MRR만 산출. 체크리스트·평가계획서는 nDCG@k도 요구한다. 지표 함수
추가만 하면 됨.

## 5. 잠정 제목·초록 (미확정 초안)

후보 제목은 두 가지가 경합 중이다.

1. (분석 강조) 공식 학사 문서 기반 RAG 시스템의 검색 실패 유형 분석 및 거절 평가
2. (시스템+분석) 대학 학사 행정 안내를 위한 공식 문서 기반 RAG 시스템 구축 및
   검색 실패 분석 — GPT 추천(구현 프로젝트 느낌 유지)

분석 논문처럼만 보이면 구현 기여가 약해 보일 수 있어 2 선호. 미결정.

잠정 초록 (GPT 초안, 수치는 재측정 후 확정):

> 본 연구는 대학 학사 행정 정보를 대상으로 공식 웹 문서 기반 RAG 시스템을
> 구축하고, 50개 학사 질의 데이터셋을 통해 검색 성능과 정답 부재 질의에 대한
> 거절 가능성을 평가한다. 실험 결과, 코퍼스 정제와 색인 개선, RRF 기반 순위 융합,
> 도메인 어휘 확장을 통해 순수 검색 기준 Recall@5 0.94, MRR 0.78을 달성하였다.
> 또한 실패 사례를 커버리지 부재, 후보풀 미진입, 병합 손실, 낮은 순위로 분류하여
> 한국어 대학 행정 문서 RAG에서 발생하는 구조적 한계를 분석하였다.

초록의 거절 프레이밍과 남은 수치는 §3 보완 항목을 반영해 확정.
