# 실험 노트 (Experiment Log)

논문을 위한 실험과 발견을 **시간순으로 누적**하는 살아있는 기록이다.
새 실험 결과가 나올 때마다 맨 아래에 항목을 덧붙인다(기존 항목은 고치지 않고,
번복·수정은 새 항목으로).

각 항목 형식:
- **날짜 / 실험 이름**
- **질문**: 무엇을 알고 싶었나
- **방법**: 어떻게 쟀나 (재현 가능하게)
- **결과**: 숫자·표
- **해석**: 무슨 뜻인가, 논문 함의
- **주의·한계**: 과대해석 방지
- **상태**: 확정 / 추가 검증 필요 / 미해결
- **재현**: 파일·명령

## EXP-01. 검색 성능 기준선 (50문항)

- **날짜**: 2026-07-05
- **질문**: 현재 시스템이 정답 문서를 얼마나 잘 찾는가.
- **방법**: 50문항(answerable 32 / insufficient 18), gold 라벨 독립 작성, 내용 기준
  매칭. insufficient는 분모에서 제외. Recall@5, MRR.
- **결과**: **순수 검색 Recall@5 0.94, MRR 0.78.** 큐레이션(Best Bets) 포함도 동일
  (Best Bets는 방학 질의만 건드림). 미스: Q025(교양필수), Q048(기숙사).
- **해석**: 1차(6/28) 0.44/0.34 → 현재 0.94/0.78. 질문을 20→50으로 늘려도 유지 →
  개선이 새 질문에 일반화됨.
- **주의**: Q018은 순수 모드에서 flaky(임베딩 미세 비결정성). N=50도 통계적으로 작음.
- **상태**: 확정. (단, BM25-only/Vector-only/Hybrid 격리 기준선표와 nDCG는 미측정 —
  05 문서 3.2/3.3 참조.)
- **재현**: `eval/run_questions.py`, `eval/results/`.

## EXP-02. 거절(abstention) 실험 — 정답 부재 질문 처리

- **날짜**: 2026-07-05
- **질문**: 정답이 코퍼스에 **없는** 질문(insufficient 18개)에 시스템은 지어내지 않고
  거절하는가? 공식 문서 기반 안내 시스템의 핵심 신뢰 요건.
- **방법**: LLM 답변 생성을 돌리지 않고 **evidence 게이트 수준**에서 측정.
  거절 결정은 LLM 앞단에서 남 — `filter_evidence_candidates`가 근거 후보를
  0개 반환하면 시스템은 "정보 없음"으로 거절해야 함. 각 질문의 evidence 개수를
  answerability와 교차. (지난 eval 실행 `evidence_candidates` 필드 재사용, 추가
  API 호출 없음.)

- **결과** — 거절 2×2:

  | | 답변 시도(evidence≥1) | 거절(evidence=0) |
  |---|---|---|
  | answerable (32) | 32 | 0 (과잉거절 없음) |
  | insufficient (18) | **16** | 2 |

  **거절 정확도 = 2/18 = 0.11.** 정답 없는 질문의 **89%에서 거절 실패**(엉뚱한
  문서를 근거로 채택 → 답변 시도). answerable 쪽 과잉거절은 0(정답 있는 건 다 살림).

- **원인**: evidence 게이트 조건이 `relevance ≥ 0.35 **OR** 키워드 겹침 ≥ 1`인데,
  **키워드 겹침 fallback이 너무 헐거움.** 질의어 하나만 겹치면 실제 답이 아닌
  문서도 통과. RAG의 고전적 함정 — 검색은 항상 뭔가를 돌려주고, 게이트가
  "여기엔 진짜 답이 없다"를 못 말함.

- **위험 16개의 뉘앙스**(균일하게 위험하지 않음 — 이 구분 자체가 findings):
  - **진짜 엉뚱**: Q005 등록금분납 → 무관 학과공지·일정 / Q030 국가근로 → 학과공지
  - **주제 인접**: Q021 졸업학점확인 → 졸업학점표 / Q043 장학부서위치 → 전화번호부 /
    Q023 학점확인 → 성적/학점인정 안내 (사람이 봐도 "가깝지만 딱 그 답은 아님")

- **해석 / 논문 함의**:
  1. **부정적 결과(강력)**: 표준 evidence-gate RAG가 정답 없는 기관 질문의 89%에서
     거절에 실패함을 실측. 대부분의 검색 평가는 answerable에서 recall만 재고 이
     차원을 안 봄 → 덜 보고된 결과.
  2. **RQ3 강화**: "insufficient 처리와 거절 정책이 왜 필요한가"에 대한 정량 근거.
  3. **작은 방법 기여 후보**: 더 엄격한/보정된 거절 정책을 설계해 2×2를 개선
     (insufficient 거절↑, answerable 유지)하면, **데이터로 동기부여된 방법 기여**.
     → 05 문서의 "알고리즘 새로움 부재" 고민에 대한 실마리.

- **주의·한계**:
  - **게이트 수준 측정**임 — 실제 LLM 출력이 환각인지까지는 미확인(엉뚱한 근거를
    받으면 답할 가능성이 높으나, LLM이 자체 hedge할 여지도 있음). 논문에선
    "게이트가 부적절한 근거를 통과시킨다"까지 주장하고, LLM 출력 확인은 별도.
  - 일부 insufficient 라벨은 경계 사례(주제 인접 문서를 사람은 "근접"으로 볼 수도).
    → 라벨 재검토가 아니라, "근접 vs 무관"을 결과 분석에서 구분해 다룸.
  - best_bets 켜짐 상태였으나 insufficient엔 트리거 없어 영향 없음.

- **상태**: **확정(게이트 수준).** 다음: 개선된 거절 정책 설계·측정(미착수),
  LLM 출력 수준 확인(선택).

- **재현**: `eval/results/retrieval-20260705-094816.jsonl`의 각 항목
  `expected_answerability` × `len(evidence_candidates)` 교차. (분석 스니펫은
  세션 로그 참조.)

## EXP-03. 거절 분리 가능성 — answerable vs insufficient가 점수로 갈리나

- **날짜**: 2026-07-05
- **질문**: EXP-02에서 거절 실패(2/18)를 확인했다. 그럼 **"진짜 답 있음 vs 없음"을
  점수 하나로 구별할 수 있나?** 구별되면 문턱(threshold)으로 거절을 고칠 수 있고,
  안 되면 더 복잡한 방법이 필요하다. 방법을 고르기 전에 이걸 먼저 봐야 한다.
- **방법**: 50문항 각각에 검색을 돌려, 최고 매치의 세 가지 점수를 answerability와
  교차. 세 신호:
  - **best_sem**: 의미 검색 top-1의 원 유사도(1/(1+distance)) — 정규화·융합 이전
    절대값. "가장 가까운 문서가 뜻으로 얼마나 가까운가".
  - **best_rel**: 병합 후 최고 relevance(가중합 정규화, 게이트가 실제로 보는 값).
  - **best_ovl**: 최고 키워드 겹침(질의어와 문서가 겹치는 개수).

- **결과** (중앙값 / 최적 단일 문턱 정확도):

  | 신호 | answerable 중앙 | insufficient 중앙 | 최적 문턱 정확도 |
  |---|---|---|---|
  | best_sem (원 의미 유사도) | 0.522 | 0.491 | **0.78** (t≈0.497: answerable 29/32 유지, insufficient 10/18 거절) |
  | best_rel (병합 relevance) | 0.542 | 0.453 | 0.74 (insufficient 5/18만 거절) |
  | best_ovl (키워드 겹침) | 1 | 1 | **0.64 — 거절 0 (무용)** |

- **해석**:
  1. **키워드 겹침은 거절에 완전히 무용.** insufficient도 겹침 중앙값이 1이라
     answerable과 안 갈린다. → EXP-02의 원인(overlap fallback이 순수 누출)을 확증.
  2. **원 의미 유사도(best_sem)가 최선의 신호.** relevance보다 나은 이유는 **절대값**
     이기 때문(relevance는 질의별 정규화라 절대 스케일을 잃음).
  3. **그래도 깨끗하게 안 갈린다.** 분포가 크게 겹침(answerable 최소 0.466 <
     insufficient 최대 0.539). 단일 문턱 천장이 0.78. **완전한 거절은 문턱으로 불가.**

- **핵심 발견 (논문 중심 주제와 연결)**:
  > **같은 어휘 갭이 검색과 거절을 동시에 무너뜨린다.** 어휘 갭 answerable 질문
  > (방학·기숙사 등, gold가 의미적으로 먼)은 유사도 관점에서 정답 없는 질문과
  > 구별되지 않는다. 반대로 주제 인접 insufficient(졸업학점확인→졸업학점표)는
  > 유사도가 높다. **두 실패 모드가 한 뿌리로 얽혀 있다.**
  이는 "거절을 못 고쳤다"가 아니라, 논문 중심 주제(어휘/커버리지 갭)가 거절에서도
  재현되는 findings다.

- **개선 방향 (미착수, 브레인스토밍 결론)**:
  - 게이트 조건 `relevance≥0.35 OR overlap≥1`에서 **누출인 overlap fallback을
    원 의미 유사도 하한으로 교체**(B+D). τ를 라벨로 보정(≈0.497).
  - 예상 트레이드오프: 거절 2/18 → ~10/18, 대신 과잉거절 0 → 3/32.
  - **주장 범위**: "거절 해결"(X) → "부분 개선 + 잔여 오류는 어휘 갭 케이스"(O).
    N=50 작으므로 문턱 하나만, 다중 신호·튜닝은 과적합 회피.

- **주의·한계**: N=50 소규모라 문턱 0.497은 이 데이터에 맞춘 값 → 별도 검증셋 없음
  (과적합 주의). 분리 천장 0.78은 "이 신호로는 여기까지"라는 상한이지 최종 성능 아님.

- **상태**: 분석 확정. 게이트 교체 구현·측정은 미착수. 과잉거절 3개가 실제로
  어휘 갭 케이스(Q018/Q048/Q025 등)인지 확인은 미실시(다음).

- **재현**: `scratchpad/abstain_sep.py` (질문당 임베딩 1회, best_sem/rel/ovl 분포와
  최적 문턱 산출). 코퍼스는 2026-07-05 dorm 시드 반영 상태.
- **문헌 정렬**: 이 발견("검색 품질이 거절 상한을 정함")은 미응답 RAG 연구선의
  "oracle 검색기 → 올바른 거절 0.68→0.93"과 정렬. evidence-충분성 거절 자체는
  2025 선행연구 존재 → 우리는 방법이 아니라 도메인 재현+얽힘 실측이 기여.
  상세: [02-related-work.md](02-related-work.md) 3축.

## EXP-04. 검색 기준선표 — BM25 only / Vector only / Hybrid + nDCG@5

- **날짜**: 2026-07-10
- **질문**: 하이브리드 융합이 단일 검색기 대비 실제로 무엇을 더 주는가.
  KMMS 체크리스트가 요구하는 격리 기준선표와 nDCG@k를 채우는 실험.
- **방법**: `eval/run_questions.py`에 `--retriever-mode {hybrid,bm25,semantic}`
  추가(설계: [docs/plans/2026-07-10-baseline-table-ndcg-eval.md](../plans/2026-07-10-baseline-table-ndcg-eval.md),
  구현: Codex 위임). 격리는 융합만 끄고 상세 확장·중복 제거·intent boost 등
  후처리는 동일. 단일 모드는 활성 검색기 가중치 1.0. nDCG@5는 binary(단일
  relevant, IDCG=1). 세 모드를 같은 코퍼스 스냅숏에서 연속 실행, best bets 없이
  순수 검색. Freshness 행은 범위 제외(08 문서 W6).

- **결과** (answerable 32 / insufficient 18):

  | 모드 | Recall@5 | MRR | nDCG@5 | 미스 수 |
  |---|---|---|---|---|
  | BM25 only | 0.4375 | 0.3854 | 0.3988 | 18 |
  | Vector only | 0.8750 | 0.8125 | 0.8289 | 4 |
  | Hybrid (RRF) | 0.9375 | 0.7760 | 0.8181 | 2 |

  하이브리드 수치는 EXP-01(0.94/0.78)과 일치 — 하네스 변경 후 회귀 없음 확인.

- **사례 분석** (어느 질문이 어느 검색기에서만 잡히는가):
  - BM25만 잡는 질문: Q003 국가장학금(rank 2), Q007 수강신청 기간(rank 1).
    둘 다 질의 키워드가 문서에 그대로 있는 정합 질의. semantic은 pool_miss.
  - Vector만 잡는 질문: BM25 미스 18개 중 16개를 semantic이 구제(Q018 포함,
    rank 1). BM25 미스는 대부분 pool_miss — 어휘 불일치·형태 변형에 취약.
  - 하이브리드는 semantic 미스 2건(Q003/Q007)을 BM25로 구제해 recall 최고.
    대신 MRR 0.8125→0.7760, nDCG 0.8289→0.8181로 소폭 하락: 융합이 recall을
    사고 top-rank 정밀도를 약간 지불하는 trade-off.
  - 모든 모드가 놓치는 질문: Q025(교양필수), Q048(기숙사) — 전 모드 pool_miss.
    검색기 선택으로 해결 안 되는 커버리지/어휘 갭 문제.

- **해석 / 논문 함의**:
  1. 기준선표 완성 — 체크리스트 §3.2/3.3 해소.
  2. 하이브리드의 가치는 "전 지표 우위"가 아니라 **상보성**이다: recall은 최고지만
     MRR/nDCG는 vector 단독이 근소 우위. 이 trade-off를 숨기지 않고 보고하는 것이
     Best Bets 분리 보고와 같은 정직성 전략.
  3. Q025/Q048이 전 모드 pool_miss인 것은 "실패는 랭킹이 아니라 그 이전 단계"
     헤드라인(05 §2.3)의 직접 증거 — 검색기를 바꿔도 못 잡는 미스.
  4. 어휘 갭의 양방향 확인: BM25는 의미 변형에, vector는 정확 키워드 정합 질의
     (기간·고유명사)에 각각 취약.

- **주의·한계**:
  - N=32라 질문 1개 = Recall 0.031. 모드 간 차이(특히 hybrid vs vector의 recall
    2문항)는 서술적 비교로만 보고하고 통계적 유의성은 주장하지 않는다(08 문서 W5).
  - BM25-only 0.4375가 1차 보고(6/28)의 풀시스템 0.44와 수치가 우연히 비슷함 —
    다른 측정이므로 혼동 주의.
  - Q018은 flaky 이력(EXP-01) — 이번 실행에서 semantic/hybrid 모두 rank 1로 잡힘.

- **상태**: 집계 수치는 확정, 사례 분석은 보류 → 하단 EXP-04 추기(2026-07-10) 참조.
- **재현**: `uv run --project backend python eval/run_questions.py
  --retriever-mode {bm25,semantic,hybrid} --no-best-bets` 연속 3회.
  결과: `eval/results/retrieval-{bm25-20260710-112650,semantic-20260710-112659,hybrid-20260710-112716}*`.

## EXP-04 추기. qrel 재검토 필요 판정

- **날짜**: 2026-07-10 (같은 날 외부 리뷰 2 반영)
- **무엇이 번복되나**: EXP-04의 사례 분석 중 "BM25만 잡는 질문 Q003/Q007",
  "전 모드 pool_miss Q025/Q048"은 qrel 재판정 전까지 논문에 쓰지 않는다.
  외부 리뷰([09](09-external-review-2026-07-10.md) §2)가 원자료에서 확인한 바:
  Q003·Q048은 vector 1위 문서가 실제 답을 포함하는데 gold URL이 아니라서 미스
  처리됐고, Q007은 대학원 일정 여부 판정 필요, Q025는 라벨 자체가 불안정하다.
- **유지되는 것**: 세 모드 집계 수치(표)와 "BM25 단독이 크게 뒤진다"는 관찰,
  하이브리드 회귀 없음 확인. 단 미스 건수 해석은 "특정 canonical URL 미회수"로
  제한하고, nDCG@5는 binary first-hit nDCG@5로 명명을 제한한다.
- **다음**: 세 모드 top-5 합집합 pooling → 미스·모드 불일치 사례 사람 재판정 →
  대체 정답 보강 → qrel 동결 → 지표 재산출. 재판정 결과는 새 항목(EXP-05
  이후)으로 기록.
- **상태**: 완료 → EXP-05 참조.

- **결과** (answerable 32, 순수 검색, qrel v2):

  | 모드 | Recall@5 | MRR | nDCG@5 | 미스 |
  |---|---|---|---|---|
  | BM25 only | 0.5000 | 0.4323 | 0.4498 | 16 |
  | Vector only | 0.9375 | 0.8906 | 0.9029 | 2 (Q003, Q007) |
  | Hybrid (RRF) | 1.0000 | 0.8229 | 0.8690 | 0 |

- **해석**:
  1. EXP-04 사례 주장 중 "전 모드 미스 Q025/Q048"은 라벨 산물로 확인 — 철회.
     정답을 담은 문서(연도별 교양필수 표, 입사신청 페이지)를 검색은 찾고
     있었고 qrel이 좁았다.
  2. "BM25만 잡는 질문 Q003(국가장학금)/Q007(수강신청 기간)"은 재판정 후에도
     유효 — semantic 미스 유지. 키워드 정합 질의에서의 상보성 사례로 논문에
     사용 가능.
  3. recall-정밀도 trade-off는 유지된다. hybrid recall 1.00 vs vector 0.94,
     반대로 MRR 0.89 vs 0.82, nDCG 0.90 vs 0.87로 vector 단독이 앞선다.
     09 리뷰 §4의 coverage-oriented operating point 서술이 그대로 유효.
  4. 부수 발견: 기관 RAG에 "대상자 스코프" 실패 축이 있다. 같은 안내라도
     대학원/특정 단과대학 전용이면 일반 질문에 오답이 된다(Q007 대학원
     학사일정, Q001 드림라이프 절차). 질문이 스코프를 명시하지 않으면 시스템도
     사람도 판정이 어렵다 — 사례 분석·한계 절 소재.
