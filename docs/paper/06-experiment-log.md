# 실험 노트 (Experiment Log)

논문을 위한 실험과 발견을 **시간순으로 누적**하는 살아있는 기록이다.
새 실험 결과가 나올 때마다 맨 아래에 항목을 덧붙인다(기존 항목은 고치지 않고,
번복·수정은 새 항목으로).

각 항목 형식:
- **날짜 / 실험 이름**
- **질문**: 무엇을 알고 싶었나
- **방법**: 어떻게 쟀나 (재현 가능하게)
- **결과**: 숫자·표
- **해석**: 무슨 뜻인가, 논문 함의
- **주의·한계**: 과대해석 방지
- **상태**: 확정 / 추가 검증 필요 / 미해결
- **재현**: 파일·명령

## EXP-01. 검색 성능 기준선 (50문항)

- **날짜**: 2026-07-05
- **질문**: 현재 시스템이 정답 문서를 얼마나 잘 찾는가.
- **방법**: 50문항(answerable 32 / insufficient 18), gold 라벨 독립 작성, 내용 기준
  매칭. insufficient는 분모에서 제외. Recall@5, MRR.
- **결과**: **순수 검색 Recall@5 0.94, MRR 0.78.** 큐레이션(Best Bets) 포함도 동일
  (Best Bets는 방학 질의만 건드림). 미스: Q025(교양필수), Q048(기숙사).
- **해석**: 1차(6/28) 0.44/0.34 → 현재 0.94/0.78. 질문을 20→50으로 늘려도 유지 →
  개선이 새 질문에 일반화됨.
- **주의**: Q018은 순수 모드에서 flaky(임베딩 미세 비결정성). N=50도 통계적으로 작음.
- **상태**: 확정. (단, BM25-only/Vector-only/Hybrid 격리 기준선표와 nDCG는 미측정 —
  05 문서 3.2/3.3 참조.)
- **재현**: `eval/run_questions.py`, `eval/results/`.

## EXP-02. 거절(abstention) 실험 — 정답 부재 질문 처리

- **날짜**: 2026-07-05
- **질문**: 정답이 코퍼스에 **없는** 질문(insufficient 18개)에 시스템은 지어내지 않고
  거절하는가? 공식 문서 기반 안내 시스템의 핵심 신뢰 요건.
- **방법**: LLM 답변 생성을 돌리지 않고 **evidence 게이트 수준**에서 측정.
  거절 결정은 LLM 앞단에서 남 — `filter_evidence_candidates`가 근거 후보를
  0개 반환하면 시스템은 "정보 없음"으로 거절해야 함. 각 질문의 evidence 개수를
  answerability와 교차. (지난 eval 실행 `evidence_candidates` 필드 재사용, 추가
  API 호출 없음.)

- **결과** — 거절 2×2:

  | | 답변 시도(evidence≥1) | 거절(evidence=0) |
  |---|---|---|
  | answerable (32) | 32 | 0 (과잉거절 없음) |
  | insufficient (18) | **16** | 2 |

  **거절 정확도 = 2/18 = 0.11.** 정답 없는 질문의 **89%에서 거절 실패**(엉뚱한
  문서를 근거로 채택 → 답변 시도). answerable 쪽 과잉거절은 0(정답 있는 건 다 살림).

- **원인**: evidence 게이트 조건이 `relevance ≥ 0.35 **OR** 키워드 겹침 ≥ 1`인데,
  **키워드 겹침 fallback이 너무 헐거움.** 질의어 하나만 겹치면 실제 답이 아닌
  문서도 통과. RAG의 고전적 함정 — 검색은 항상 뭔가를 돌려주고, 게이트가
  "여기엔 진짜 답이 없다"를 못 말함.

- **위험 16개의 뉘앙스**(균일하게 위험하지 않음 — 이 구분 자체가 findings):
  - **진짜 엉뚱**: Q005 등록금분납 → 무관 학과공지·일정 / Q030 국가근로 → 학과공지
  - **주제 인접**: Q021 졸업학점확인 → 졸업학점표 / Q043 장학부서위치 → 전화번호부 /
    Q023 학점확인 → 성적/학점인정 안내 (사람이 봐도 "가깝지만 딱 그 답은 아님")

- **해석 / 논문 함의**:
  1. **부정적 결과(강력)**: 표준 evidence-gate RAG가 정답 없는 기관 질문의 89%에서
     거절에 실패함을 실측. 대부분의 검색 평가는 answerable에서 recall만 재고 이
     차원을 안 봄 → 덜 보고된 결과.
  2. **RQ3 강화**: "insufficient 처리와 거절 정책이 왜 필요한가"에 대한 정량 근거.
  3. **작은 방법 기여 후보**: 더 엄격한/보정된 거절 정책을 설계해 2×2를 개선
     (insufficient 거절↑, answerable 유지)하면, **데이터로 동기부여된 방법 기여**.
     → 05 문서의 "알고리즘 새로움 부재" 고민에 대한 실마리.

- **주의·한계**:
  - **게이트 수준 측정**임 — 실제 LLM 출력이 환각인지까지는 미확인(엉뚱한 근거를
    받으면 답할 가능성이 높으나, LLM이 자체 hedge할 여지도 있음). 논문에선
    "게이트가 부적절한 근거를 통과시킨다"까지 주장하고, LLM 출력 확인은 별도.
  - 일부 insufficient 라벨은 경계 사례(주제 인접 문서를 사람은 "근접"으로 볼 수도).
    → 라벨 재검토가 아니라, "근접 vs 무관"을 결과 분석에서 구분해 다룸.
  - best_bets 켜짐 상태였으나 insufficient엔 트리거 없어 영향 없음.

- **상태**: **확정(게이트 수준).** 다음: 개선된 거절 정책 설계·측정(미착수),
  LLM 출력 수준 확인(선택).

- **재현**: `eval/results/retrieval-20260705-094816.jsonl`의 각 항목
  `expected_answerability` × `len(evidence_candidates)` 교차. (분석 스니펫은
  세션 로그 참조.)
