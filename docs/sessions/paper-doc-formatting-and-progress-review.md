## 1. 형식 원칙: 장치마다 역할을 하나로

문제 인식이 시작점이었다. 05, 07 문서가 볼드·번호 제목·표·인용문을 다 쓰고 있는데,
각 장치가 하나의 역할만 맡지 않고 다 섞여 있었다. 예를 들어 인용문(>)이 한 문서 안에서
세 가지 역할을 겸했다. 핵심 결론을 강조할 때도, "논문에 이렇게 쓰자"는 예시 문장에도,
주의사항 각주에도. 그래서 `>` 마크가 보여도 이게 강조인지 예시인지 곁다리인지
독자가 구분할 수 없었다.

이후 논문 문서에서는 다음 규칙을 지킨다.

### 1.1 인용문(>)은 "논문 본문 후보 문장"에만

강조·결론·각주 목적으로 쓰지 않는다. 인용문 안의 내용은 "그대로 논문에 넣을 수도 있는
문장"만 담는다. 예: 잠정 초록, thesis 후보 문장, "논문에 이렇게 쓰면 위험한/안전한"
예시 문장. 결론이나 후속 안내는 그냥 문단으로 쓴다.

### 1.2 표는 "가로세로 둘 다 의미 있는" 진짜 대조표에만

목록에 가까운데 표로 만들면 독자 눈이 "대조표구나" 하고 반응하지 못한다. 살릴 표의
기준은 다음.

- 실패층 × 의미 × 대응 방향 (07 §3.2)
- 비교축 × GPT 검색 × Campus Copilot (07 §3.4)
- 분량 × 섹션 × 내용 (8페이지 구성)

"주장 | 보류 이유", "미결정 | 권고", "말할 수 있는 것 / 위험한 것" 같은 목록성은
표로 만들지 않고 그냥 목록으로 쓴다.

### 1.3 볼드는 라벨과 절대 결론 한 문장에만

문장마다 볼드를 뿌리면 강조가 상쇄된다. 볼드를 남길 위치는 다음.

- "확정 / 미결정 / 폐기" 같은 상태 라벨
- 절 전체를 관통하는 한 문장 결론

그 외 "가장 위험한 문장", "가장 안전한 문장" 같은 준-강조는 그냥 평문으로 쓴다.

### 1.4 제목은 번호가 계층이면 짧게

`## 3. ### 3.1`처럼 번호가 이미 계층 구조를 표시하고 있으면 제목은 짧게 쓴다.
이모지(⚠️ ✅), 꼬리표("— 가장 중요한 수정", "(⚠️ 결정 필요)"), 부제는 빼고 명사로만.

### 1.5 설명·판단은 평범한 문단으로

박스·표·인용문에 담지 말고 그냥 문단으로 쓴다. 장치는 예외적인 경우에만 쓰라고 있는
것이지 모든 문장을 담는 그릇이 아니다.

## 2. 3주 궤적 크로스체크

세션 후반에 "지금까지 뭘 한 거지"라는 자기 의심 국면이 있었고, Claude Code 세션
5개(총 15MB)와 Codex 세션 수십 개, git 커밋 54개를 대조해 최근 3주 활동을 정리했다.
논문 집필 시 서론·시스템 절의 사실 확인용으로 참조할 수 있게 여기 요약을 남긴다.

### 2.1 6/28

일요일 하루 만에 커밋 15개. 20문항 gold 라벨링을 도메인 판정으로 직접(Q003 장학,
Q005 등록금 우편, Q013 증명서). insufficient를 분모에서 빼고 별도 카운트하는 결정도
이 날. 파싱 대개조(캘린더 그리드 스킵, hidden skip-nav 스킵, DOM 헤딩에서 문서 제목 추출,
복합어/굴절어 매칭, 미러 문서 dedupe, 의도 인식 랭킹 부스트). 저녁에 1차 교수 리포트.

### 2.2 6/29~6/30

크롤 파이프라인 페이즈 분리 리팩터링. `run_crawl` 원페이즈를 재사용 가능한 pass들로
분해. fetch artifact 캐시, cross-process advisory lock, PDF write-through,
phase orchestrator + CLI, discovery target 저장하고 거기서 재파싱하는 구조.
grill-me로 방향 잡고 → Claude에 구현 → Codex에 리뷰 → 증분 커밋으로 흐름을 굳힌 시점.

### 2.3 7/2

크롤 CLI 문서화(현재 CLAUDE.md), articleBox 자식 링크 페이지네이션 좁힘, calendar 그리드
markdown 경로 수정, 게시글 상세 공지 분류, 문서 제목·메뉴 컨텍스트를 청크 앞에 붙여
임베딩, 공지 강등 및 문서 다양화, 미스 진단용 candidate pool visibility. 커밋 11개.

### 2.4 7/4

RRF 도입. 하이브리드 결과를 RRF로 융합하면서 evidence relevance를 분리한 결정 —
07 §3.6 "관찰" 항목의 근원. 연락처 어휘 갭 브리지, doc search keywords로 BM25 확장,
임베딩 재사용 최적화. "방학 ↔ 개강" 어휘 유사도 문제 인지. Gemini flash-lite 보조 도입.

### 2.5 7/5

어휘 갭 다섯 가지 시도 실패의 날. 키워드 생성 default-off 게이팅 후 롤백. Best Bets
도입. 질문 20→50 확장, 전 문항 gold 완료. 기숙사 사이트 시드. 2차 교수 리포트. 커밋 10개.

### 2.6 7/7

논문 축으로 이동. 3자 논의(사용자+Claude+GPT) 종합으로 05 스코핑 문서 작성. 거절 실험
EXP-02 실행(2/18 부정적 결과), EXP-03 abstention separability. 관련 연구를 2025-26
소스로 재구성, citation 태그 축 분리, arxiv 링크 정규화.

### 2.7 7/8 (오늘)

GPT Pro 외부 리뷰 문서(07) 작성. 형식 원칙 반영(§1). 이 세션 문서 작성.

### 2.8 3주 총량

- 커밋 54개
- 코드: 크롤 페이즈 분리, BM25+벡터+RRF+evidence gate+Best Bets, 키워드 생성 게이팅
- 평가: 20→50문항, 전 문항 gold, answerable 32 / insufficient 18, 실패 유형 분류 코드
- 실험: 검색 성능 0.44→0.94 단계별, RRF vs 가중합, 어휘 갭 해결 5개 실패,
  EXP-02 거절 2/18, EXP-03 분리성
- 문서: 1차·2차 교수 리포트, 크롤 CLI 문서, 세션 문서 다수, 논문 문서 7개
