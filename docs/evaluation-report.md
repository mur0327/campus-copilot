# Campus Copilot 문서 검색 성능 평가 — 중간 보고

작성일: 2026-06-28

## 1. 무엇을 만들고 있나

대학 학사 정보를 자연어 질문으로 찾아주는 RAG(검색 증강 생성) 안내 시스템이다.
사용자가 "휴학 신청은 어떻게 하나요?"처럼 물으면, 학교 공식 웹페이지를 자동 수집·색인해 두었다가
질문과 관련된 문서를 찾아(검색) 그 근거로 답변을 생성한다.

이번 보고는 그중 **"검색" 단계가 실제로 정답 문서를 잘 찾는가**를 측정한 결과다.
(답변 생성 품질이 아니라, 그 앞단인 문서 검색 성능에 집중한다. 검색이 틀리면 답변도 틀리기 때문이다.)

## 2. 평가 방법

### 2.1 평가용 질문 (20개)

실제 학생이 물을 법한 대표 질문 20개를 만들었다. 10개 영역 각 2문항이다.
(휴학·복학, 장학금, 등록금, 수강신청, 졸업·학점, 성적·시험, 증명서, 입학·편입, 학사일정, 부서·문의처)

### 2.2 정답 기준 만들기 (핵심)

질문마다 **"이 질문의 공식 정답 페이지는 무엇인가"** 를 사람이 직접 확인해 기록했다.
이를 정답 기준(ground truth)이라 한다. 채점을 위해 반드시 필요하다.

이때 두 가지 원칙을 지켰다.

- **검색 결과를 보고 정답을 정하지 않았다.** 전체 수집 문서에서 독립적으로 정답을 찾았다.
  (검색이 찾아준 것 중에서 정답을 고르면, 검색이 놓친 정답은 영원히 안 보여 평가가 부풀려진다.)
- **정답이 수집 문서에 아예 없는 질문은 따로 분류했다.** 20개 중 4개가 여기 해당한다.
  이런 질문은 검색 성능 점수에서 제외하고 별도로 보고한다.
  (검색이 못 찾은 게 아니라, 애초에 찾을 페이지가 없는 경우다. 검색 품질과 자료 커버리지는 다른 문제다.)

정답이 존재하는 질문은 16개, 정답 자체가 없는 질문은 4개였다.

### 2.3 채점 지표

- **Recall@5**: 정답 문서가 검색 상위 5개 안에 들어왔는가 (들어오면 성공)
- **MRR**: 정답이 평균적으로 몇 번째에 나오는가 (앞에 나올수록 1에 가까움)

또한 같은 내용 문서가 여러 학과 홈페이지에 복제돼 있어, 단순 주소(URL) 비교가 아니라
**내용 기준으로 정답 도달 여부를 판정**했다.

## 3. 결과

정답이 존재하는 16개 질문 기준이다.

| 지표 | 값 | 해석 |
| --- | --- | --- |
| Recall@5 | 0.44 (16개 중 7개 성공) | 상위 5개 안에 정답이 드는 비율 |
| MRR | 0.27 → 0.34 | 검색 순위 개선 작업 후 향상 |

정답 자체가 없던 4개 질문은 별도 한계 항목으로 보고한다(아래 5장).

## 4. 핵심 발견: "왜 못 찾는가"를 계층으로 분해

가장 중요한 결과는 점수 자체가 아니라 **실패 원인의 구조**다.

정답을 못 찾은 9개 질문을 분석하니, 그중 **8개는 "정답 문서가 검색 후보에 아예 등장하지 않음"** 이었다.
즉 순위를 잘 매기고 말고의 문제가 아니라, 정답이 후보 목록에 들어오지도 못하는 문제다.
원인은 단일하지 않고 다음 네 계층으로 나뉜다.

1. **문서 파싱 품질 문제 (발견 후 수정함)**
   - 학사일정 페이지의 달력 표가 의미 없는 숫자 격자(요일:날짜)로 추출되어, 검색에 쓸 수 없는 형태였다.
     달력 표를 걸러내도록 수정했다.
   - 수집된 문서의 **약 99%가 제목이 비어 있었다.** 제목은 검색의 강한 단서인데 통째로 빠져 있었다.
     페이지 머리글에서 제목을 추출하도록 수정했다.

2. **자료 커버리지 한계 (구조적)**
   일부 정보는 애초에 정적 웹페이지로 존재하지 않는다. 예: 개인별로 우편·문자로 안내되는 등록금 납부,
   PDF 뷰어로만 제공돼 본문 추출이 안 되는 편입 모집요강, 카카오톡으로 연결되는 입학 상담 배너 등.

3. **표현 어휘 차이**
   질문은 "방학", "시험"이라 하지만 문서는 "계절학기", "중간·기말고사"로만 적혀 있어 매칭이 약하다.

4. **검색 순위 경쟁 (개선함)**
   정답 문서가 학과 공지·중복 문서에 밀려 순위가 낮아지는 경우. 질문 의도(절차/시점/조건/연락처)를
   반영한 순위 보정을 도입해 개선했고, 이미 잘 맞던 문항을 망치지 않도록 회귀 검증을 함께 했다.

## 5. 개선 작업과 검증

- **검색 순위 개선(완료·측정됨)**: 질문 의도를 인식해 적합한 유형의 문서를 우대/감점.
  MRR이 0.27 → 0.34로 약 24% 향상되었고, 기존에 잘 맞던 질문이 나빠지지 않음을 테스트로 확인했다.
- **파싱 품질 개선(구현 완료, 코퍼스 재반영 예정)**: 달력 표 제거, 문서 제목 추출.
  전체 문서 재색인 후 검색 성능에 미치는 효과를 측정할 계획이다.
- **자료 커버리지 한계(4개 질문)**: 원인별로 분류해 한계로 명시했다. 무리하게 정답을 만들지 않았다.

## 6. 의의와 다음 단계

이번 평가의 메시지는 "검색이 잘 된다"가 아니라,

> **현실 기관의 RAG는 검색 성능 상한이 자료의 커버리지와 파싱 품질에 의해 결정되며,
> 본 연구는 그 경계를 측정으로 드러내고 원인을 계층화했다.**

는 것이다. 향후 과제는 다음과 같다.

1. 수집·파싱 파이프라인을 단계별로 분리해, 전체 재수집 없이 파싱·색인만 저비용으로 다시 돌릴 수 있게 한다.
2. 위 파싱 개선을 반영해 검색 성능을 재측정한다.
3. 어휘 차이(동의어) 대응과 정답 라벨 확장(20 → 50문항)으로 평가의 통계적 신뢰도를 높인다.

## 7. 용어 사전

| 용어 | 뜻 |
| --- | --- |
| RAG (검색 증강 생성) | 질문과 관련된 문서를 먼저 검색하고, 그 문서를 근거로 답변을 생성하는 방식. 모델이 아는 것에만 의존하지 않고 외부 자료를 끌어와 답한다. |
| 검색 (retrieval) | 질문에 대해 수집된 문서 중 관련 있는 것을 골라오는 단계. 본 보고의 평가 대상. |
| 코퍼스 (corpus) | 시스템이 수집·색인해 둔 전체 문서 집합. 여기서는 호남대 공식 웹페이지 모음. |
| 정답 기준 (gold / ground truth) | 각 질문의 "공식 정답 페이지"를 사람이 미리 정해 둔 채점 기준. 검색 결과를 이것과 비교해 맞고 틀림을 판정한다. |
| 정답 부재 (insufficient) | 질문의 정답이 코퍼스에 아예 존재하지 않는 경우. 검색이 못 찾은 게 아니므로 점수 분모에서 제외하고 따로 보고한다. |
| Recall@5 | 정답 문서가 검색 결과 상위 5개 안에 포함된 비율. 높을수록 좋다. |
| MRR (평균 역순위) | 정답이 평균적으로 몇 번째에 나오는지를 1/순위로 환산해 평균낸 값. 정답이 앞에 나올수록 1에 가깝다. |
| 파싱 (parsing) | 수집한 웹페이지(HTML)에서 본문·표·제목 등 의미 있는 텍스트를 뽑아내는 과정. |
| 청크 (chunk) | 문서를 검색·임베딩하기 좋게 자른 작은 텍스트 조각. |
| 임베딩 (embedding) | 텍스트를 의미를 담은 숫자 벡터로 바꾼 것. 의미가 비슷하면 벡터도 가깝다. |
| 벡터 검색 (semantic) | 임베딩 벡터의 유사도로 의미가 비슷한 문서를 찾는 방식. 표현이 달라도 의미로 매칭된다. |
| BM25 (키워드 검색) | 질문과 문서의 단어 일치도로 점수를 매기는 고전적 검색. 정확한 단어가 겹쳐야 잘 잡힌다. |
| 하이브리드 검색 | 벡터 검색과 BM25를 함께 써서 두 방식의 장점을 결합한 검색. 본 시스템이 사용. |
| 커버리지 (coverage) | 답에 필요한 정보가 코퍼스에 얼마나 들어와 있는지의 정도. 낮으면 검색이 아무리 좋아도 못 찾는다. |
| 의도 인식 순위 보정 | 질문이 무엇을 묻는지(절차/시점/조건/연락처)를 판별해, 그에 맞는 유형의 문서를 검색 순위에서 우대/감점하는 보정. |
